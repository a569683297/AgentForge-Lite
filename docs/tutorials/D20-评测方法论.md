## 一、今天为什么不是"写功能的一天"

从 D01 到 D19，每天都在往系统里加东西。今天反过来：**先搞清楚"怎么知道它好不好"**。

理由很直接 —— D21 起要建评测集、D22 要建打分服务、D23 要跑三配置对比。
这三件事**全部**由今天的决策决定：

- 评测集怎么设计（有没有负例？难度怎么分布？）→ 决定 D23 的结论**有没有信息量**
- 打分用什么口径（二值化？几维？）→ 决定分数**能不能比较**
- 裁判的误差有多大 → 决定"提升 10%"这个结论**敢不敢下**

> ⚠️ 一个前提：**评测集不是"随便找 50 个问题"**。它是整套体系的地基，冻结之后 D22/D23/D24 全建立在其上。
> 地基建歪，后面四项全部作废。

## 二、评测要回答三个层次完全不同的问题

| 层次 | 问题 | 靠什么答 | 缺了会怎样 |
|---|---|---|---|
| **① 相对** | C 比 A 好吗？好多少？ | 同一评测集跑三配置 | 无法回答"重排有没有用" |
| **② 绝对** | 88% 这条线过了吗？ | judge 打分 + 二值化 | 可能"三配置都很差，但 C 比 A 好 10%" |
| **③ 归因** | 差在哪类题、哪个维度？ | `eval_case_results` 逐条明细 | 只知道"分数低"，**不知道为什么** |

第三层是 v4.1 专门补的（F7.10）：`eval_runs` 只有汇总分，而**汇总分不可再下钻**；
报告要求"失败案例各取 3 条"，没有明细表根本取不出来。

> 与 D19 的 `retriever` 字段是**同一条思路**：结论必须**可归因**。
> D19 问"这条结果是重排产的还是降级来的"，D20 问"这次失分是 A 类还是 C 类、是正确性还是忠实度"。
> **面试可讲的版本：没有归因能力的指标不是指标，只是分数。**

## 三、核心机制：LLM-as-judge

- **它是什么、怎么来的、三种用法（pointwise / pairwise / reference-based）** → `D20-术语卡.md` §1
- **为什么传统两条路（字符串匹配 / 人工打分）在 RAG 上都不通** → 同上
- **它是"有误差的测量仪器"，不是标准答案** → 同上

三条**直接决定 D22 怎么写代码**的推论：

1. **能用 `assert` 精确判的就别用 judge。** C 类工具调用题（选没选对工具、参数对不对）
   是**可精确校验**的 → A/B 类走 judge，**C 类走精确校验**，只有"选对了但措辞难判"的残余才兜给 judge。
2. **judge 必须显式锁通道、失败不降级。** 走网关的 `_call_with_failover` 会出现
   "一部分样本 deepseek 打、一部分 relay 打"，而报告只写一个 judge 名 —— **抖动测量被污染**。
3. **"3 次重复"重复的是 judge，不是生成。** 评测拆两阶段：
   ① 三配置各跑一遍 50 条 → 答案 + 检索结果落库（生成只做 1 次）；
   ② 对已落库的答案重复打分 → 取多数。
   若生成也 ×3，成本翻三倍，**还把"生成抖动"混进"judge 抖动"，两个噪声源再也分不开**。

## 四、消融实验：只变一个变量，且必须可归因

`RETRIEVER_CONFIG` 一个变量，其他全不动：同一评测集、同一 judge、同一 prompt、同一 temperature、同一批语料。
**D19 做三配置可切，就是为了让"只变这一个"物理上成立。**

四条纪律：

| # | 纪律 | 违反的后果 |
|---|---|---|
| 1 | **绝不拿评测集调参** | 写完评测集、看一眼哪条挂了就去改 prompt 再重跑 = 把评测集背下来了（数据泄漏） |
| 2 | **"提升 10%"必须写清是相对还是绝对** | C=88%、A=80%：相对 +10%（达标）、绝对 +8 个百分点（没到）。报哪个是两个故事 |
| 3 | **样本量必须一起报** | 50 条里 1 条 = 2 个百分点。"提升 10%（+5 条题）"比只写"提升 10%"诚实得多 |
| 4 | **分类别出分** | C 类只有 10 条，全崩也只影响总分 20 个百分点，容易被 A 类高分掩盖 |

## 五、★今天最有价值的产出：噪声门槛有了实数

**这是本日唯一一个"以后可以直接引用"的数字。**

### 5.1 先修量具，再量东西

第 1 轮的 ε = 0 **是个假数**：judge 实际只用了 `{0,2,3,5}` 四档，**4 分档一条都没有**，
而二值化阈值恰好是 `≥4` → 阈值带（3.5~4.5）是空的 → 翻转概率**必然**为 0。
（与 D18「拿 12 token 的句子测出 2.8ms」同族：**测量对象选错**。）

第 2 轮三处修正后，量具合格：

| | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 4 分档样本数 | **0** | **12 / 17** |
| 全程空置档 | 1 分、4 分 | **无** |
| **ε** | **0.0000（假数）** | **0.0095 / 0.0190** |
| **判定门槛** | **0.00 条（不可用）** | **2.9 / 4.6 条** |

### 5.2 门槛表（50 条题规模）

| 指标 | deepseek | relay-gpt |
|---|---|---|
| ε（单次判定不一致率） | **0.95%** | **1.90%** |
| ε 的 95% Wilson 区间 | 0.17% ~ **5.20%** | 0.52% ~ **6.68%** |
| 纯噪声期望差异 | 0.94 条 | 1.87 条 |
| **判定门槛（地板 + 2σ）** | **≤ 2.9 条** | **≤ 4.6 条** |

### 5.3 拿它对照 PRD 的验收线

PRD S2：**"混合+重排 vs 纯向量 ≥ +10%"**。50 条题上 **+10% 相对提升 ≈ 4 条题**（80%→88%）。

| 打分方式 | deepseek 门槛 | relay 门槛 | 4 条题能判出来吗 |
|---|---|---|---|
| **单次** | 2.9 条 | 4.6 条 | deepseek **勉强**（余量 1.1 条）；relay **判不出** |
| **3 次多数投票** | **0.36 条** | **0.76 条** | **轻松** |

> ✅ **"要不要 3 次重复"有确定答案：要。** 它把"恰好卡在噪声边缘"变成"余量充足"，
> 而且**按 Wilson 上限这种保守口径依然成立**（3 次后上限口径 2.5 / 3.5 条，仍 < 4）。

⚠️ **一条不敢保证的前提**：多数投票能降噪，前提是**各次误差独立**。
同一模型对同一份答案常有**系统性偏好**（这答案它就是看不顺眼，5 次全判错）—— **投票救不了同向偏差**。
本轮数据无法验证独立性 → **0.36 / 0.76 条应视为乐观下限**，真实门槛介于它与单次门槛之间。
（验证方法已列入 D21 待办。）

## 六、三问判分要点（详见术语卡 §6）

| 题 | 考什么 | 要点 |
|---|---|---|
| **Q1** | 相对 vs 绝对口径，以及噪声 | 相对 **+10%** 与绝对 **+8 个百分点** 是**两个数、都要写**；「提升 8%」是**口径混乱**（会被读成相对值）。4 条题的差异**落在抖动范围内 → 不构成显著提升**。⚠️ 用一个口径否掉提升、却留下另一个，是**双标** |
| **Q2** | 偏差在哪一层生效 | 术语是 **self-preference bias**。它**不影响 A/B/C 对比**（三配置共用同一 judge、偏差同向），**只影响绝对分数**（整体偏高 → "88% 过线"的判定被放松）。⚠️ 前提是偏差**同向同量** —— **长度偏差不一定**：若 C 配置更容易产出长答案（重排把长片段排前），就会引入配置间的非等量偏差 |
| **Q3** | 负例与分母 | 致命点不是"有偏差"，而是**分母不同 → 三个分数不在同一把尺子上**：`分母 = 50 − 拒答数`，而 C 召回到更多片段 → 更少拒答 → 分母更小。另外两条：正确拒答被**无偿剔除**（等于删掉一个测试项）；"答了/没答"的判定本身要靠额外规则，引入可钻空子的环节 |

## 七、今天踩的坑（都是"不报错但数字错"那一族）

| # | 坑 | 后果 | 修法 |
|---|---|---|---|
| 1 | 样本"我以为的边界"≠ judge 眼里的边界 | ε = 0 假数 | **加难度梯度样本 G1~G7**，把质量谱压进阈值带 |
| 2 | rubric 档位描述笼统 | 1 分 / 4 分档空置 | 三档判据写具体 + 给反例（"答 20 天 vs 参考 5 天"） |
| 3 | 计时起点写在并发锁**外面** | "单次耗时"含排队 → deepseek 报成 **11.74s**（真实 **0.84s**，差 14 倍） | 拆 `request` / `e2e` 两个口径 + **内置自检**（理论 ÷ 墙钟 ≈ 1） |
| 4 | 依赖 Bash `grep` 核验改动 | 多次返回空，误判"编辑没生效" | 改用检索工具（ripgrep） |

> 第 3 条最值得记：它**不报错、不崩溃、断言全绿**，只是数字悄悄错掉。
> 若无自检，我会拿它算出"relay 比 deepseek 慢 13 倍"—— 正确是 **19.6 倍**，**差一个数量级**。
