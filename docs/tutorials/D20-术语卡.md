# D20 术语卡 · 评测体系名词逐条解释

> **为什么有这份卡**：D20 讲评测方法论时，我直接用了 `LLM-as-judge` 而没先定义，
> 用户回问「你这个是什么意思？我没懂，一个名词出来，你不应该先解释名词吗」。
> 同一条消息里 `rubric` / `消融` / `二值化` / `负例` 也都没解释就用了。
> 已把「任何领域概念词首次出现必须当场解释」写进 `agentforge-mentor` 铁律 3 第 7 条。
> 这张卡就是那些定义的落点 —— **判据不是"这词难不难"，而是"用户有没有定义过"。**

**读法**：每个词给「中文名 + 一句话定义 + 出处 + 类比 + 它长什么样（入口 → 步骤 → 返回）」。
本卡不占教程 §1–§7 编号。

## §1 消融（ablation）★ 本次重点

**中文名**：消融 / 消融实验 / 消融研究
**出处**：ablation 源自拉丁语 *ablatio*（带走、切除）。医学里的「射频消融术」就是同一词 —— 把异常传导通路烧掉。

**一句话定义**：**把系统里的某个部件拿掉，重测一遍，看性能掉多少。掉掉的那部分，就是这个部件的净贡献。**

这层含义的学名是 **归因（attribution）** —— 把一个总效果拆到各个部件头上。

**类比（前端视角）**：
想象你给打包产物做了三项优化（代码分割 + tree-shaking + 并行压缩），构建产物从 1.2 MB 降到 0.7 MB。
但**是哪一项贡献的？** 想回答就得**一次只关一项**，分别构建，比较体积。
「一次只关一项、分别构建、比差值」——这就是消融。**如果你一把全开、一把全关，你只知道总效果，永远不知道谁在起作用。**

### 两种等价写法（别被名字绕晕）

| 写法 | 做法 | 叙事方向 |
|---|---|---|
| **移除式**（经典消融） | 从最全的 C 出发，逐个拿掉：C → B → A | 看"掉"多少 |
| **叠加式**（增量） | 从 A 出发，逐个加上：A → B → C | 看"涨"多少 |

**两者的 Δ 完全一样**，只是叙述方向相反。本项目用 A / B / C **并列跑**，等价于叠加式的三档。

### 本项目里的具体形态

唯一变化的变量是 `settings.retriever_config`：

| 配置 | 向量检索 | BM25 | RRF 融合 | bge-reranker | 这一档测什么 |
|---|---|---|---|---|---|
| **A** `pure_vector` | ✓ | — | — | — | **基准线**（baseline / 对照组） |
| **B** `hybrid` | ✓ | ✓ | ✓ | — | **Δ(B−A)** = BM25 + RRF 的净贡献 |
| **C** `hybrid_rerank` | ✓ | ✓ | ✓ | ✓ | **Δ(C−B)** = 重排的净贡献 |

验收口径：**PRD §S2 —— C 相对 A ≥ +10%**。

### 它长什么样（入口 → 步骤 → 返回）

```
入口：同一份冻结的 50 条评测集
步骤：① 置 retriever_config="pure_vector"    → 跑 50 条 → 落库
      ② 置 retriever_config="hybrid"         → 跑 50 条 → 落库
      ③ 置 retriever_config="hybrid_rerank"  → 跑 50 条 → 落库
      ④ 同一套二值化规则算出三个准确率 → 相减
返回：A / B / C 三个数 + 两个 Δ（Δ(B−A)、Δ(C−B)）
```

### 怎么读这三个数

- Δ(B−A) 很小甚至为负 → BM25 那一路没帮上忙（可能语料里专有名词 / 术语不够多）
- Δ(C−B) 很小甚至为负 → **重排是负资产**，那 759 ms 净成本该省掉
- **三个数都要报**，不能只报"C 比 A 高"

### 三个前提，破一个实验就废

1. **只变一个变量** —— 同一份评测集、同一个 judge、同样的二值化规则、**分母一致**，唯一变的是那三个 config。
   这正是 D19 做「检索配置化」的目的：**同一份测试用例要能构建 3 个 build**。
   若直接把重排塞进 `search()`，B 配置会永久消失，"重排到底有没有用"以后再也答不出来。
2. **分母必须一致** —— 今天探针测出的 relay-gpt **20% 失败率**就是活的反例：
   某些配置少算几条题，分母一变，三个百分比**根本不可比**。
3. **Δ 必须显著大于噪声** —— 见 §6。

### 别和 A/B 测试搞混

| | **消融实验** | **A/B 测试** |
|---|---|---|
| 环境 | 离线、固定评测集 | 线上、真实用户分流 |
| 看什么 | 检索 / 回答**质量指标** | **业务指标**（点击、留存） |
| 目的 | **归因**：是哪个部件带来的提升 | **决策**：新版本要不要全量上线 |

我们做的是前者。

## §2 LLM-as-judge

**中文名**：用大模型当裁判 / 模型即评审
**出处**：2023 年起成为 LLM 评测的主流做法（如 MT-Bench、AlpacaEval）。

**一句话定义**：**不用人工、也不只用字面匹配，而是让另一个 LLM 读懂"参考答案"和"系统答案"，然后判系统答案好不好。**

**为什么需要**：RAG 的回答是自然语言。字面匹配（关键词是否命中）会把"**意思对了但换了个说法**"判成错；人工标注又贵又慢。
LLM 能读懂语义，所以拿它当**可以批量、可以重复**的裁判。

**类比（前端视角）**：像把断言从 `expect(text).toContain("1.2亿元")` 换成"**请一位人来看这段输出对不对**"。
更聪明、更能容忍表述差异，但**引入了新的不确定性** —— 这位"人"每次判得可能不一样。所以必须测它的抖动（§6）。

**两种打分范式**：

| 范式 | 做法 | 特点 |
|---|---|---|
| **pointwise** | 单独给**一条**答案打分 | 能出绝对分；但分档标准会漂 |
| **pairwise** | 给**两条**答案，判哪个更好 | 更稳、更接近人类偏好；但**给不出绝对准确率** |

本项目用 **pointwise**（要算 A/B/C 三配置各自的准确率，必须有绝对分）。

**它长什么样（入口 → 步骤 → 返回）**

```
入口：(问题, 参考答案, 检索到的片段, 系统生成的答案)
步骤：① 拼一个 judge prompt —— 含 rubric（§3）+ 要求输出 JSON 分数
      ② 走 LLM Gateway 调 judge 模型（temperature=0）
      ③ 解析 JSON → 得到 correctness / faithfulness / completeness 三个分
返回：三个 0~5 的整数分（本项目的档位）
```

**⚠️ 关键认知**：**judge 是一台"有误差的测量仪器"，不是标准答案。**
它的分数是**测量值**，带噪声；噪声决定了你能分辨多小的差异（§6）。这一点决定"提升 10% 是否显著"能不能下结论。

## §3 rubric

**中文名**：评分细则 / 评分量表
**出处**：教育评估领域的标准词（rubric = 评分标准表），被 LLM 评测直接沿用。

**一句话定义**：**把"好"和"不好"拆成可操作的档位判据，让不同次、不同模型的打分有同一把尺子。**

**为什么需要**：如果你只说"给这段答案打 0~5 分"，judge 每次的松紧标准都不一样，分数就不可比。
rubric 把每档**写具体**，比如：

| 档位 | correctness 的判据（第 2 轮修订版） |
|---|---|
| 5 | 关键事实全部正确且表述完整 |
| **4** | **关键事实正确，但 (a) 表述简略/啰嗦 或 (b) 附带不冲突的常识补充** |
| 3 | 关键事实部分正确 |
| **1** | **与参考答案明确冲突（给出不同关键数值）** |
| 0 | **完全没回答该问题**（跑题 / 纯空话 / 无实质内容） |

**本项目踩过的坑**：第 1 轮判分只用了 `{0, 2, 3, 5}` 四档，**1 分和 4 分全程空置**。
- **4 分空置** → 阈值带（3.5~4.5）是空的 → 翻转率必然为 0（见 §6）
- **1 分空置** → `0 = 完全无关` 与 `1 = 与参考答案冲突` 分界不清，"答错了但答到了点上"被一律压到 0，**丢掉了"错得多离谱"这个区分度**

**类比（前端视角）**：像把 ESLint 的 `error` 规则从"代码不好"写成具体条目。
规则越模糊，不同人跑出来的结果差异越大。**rubric 就是 judge 的 lint 规则表。**

## §4 二值化（binarization）

**中文名**：二值化 / 阈值化
**一句话定义**：**把连续或多档的分数，按一个阈值压成"是 / 否"，以便算出"答对率"这样的百分比。**

**为什么需要**：judge 给的是 0~5 的档位分，但"准确率 62%"这种说法需要一个**是/否**的判定。

**本项目口径**：`correctness ≥ 4` 记为"答对"，否则"答错"。

**类比（前端视角）**：像把 Lighthouse 的连续评分（0~100）按 `≥ 90` 判成"通过"。
**注意：阈值是人为选的，换一个阈值结论可能就变了** —— 这正是本项目的问题所在：

```
judge 实际用到的档位 = {0, 2, 3, 5}
                        ↑ 没有 1      ↑ 没有 4
阈值 = correctness ≥ 4
```

**没有任何一条样本落在 4 分附近**（要么 5、要么 ≤3）→ **阈值带（3.5~4.5）是空的**
→ 单次判定翻转的概率**必然为 0**，与 judge 稳不稳**无关**。

> 这与 D18「拿 12 token 的句子测出 2.8 ms」是**同一族错误**：
> **测量对象选错，得到一个看似精确、实则荒谬的数。**

## §5 负例（negative sample）

**中文名**：负例 / 反例 / 拒答题
**出处**：机器学习里的正负样本概念，评测集设计沿用。

**一句话定义**：**评测集里那些"答案本来就不存在、正确行为是不回答 / 说不知道"的题。**

**为什么必须放**（PRD 要求 50 条里至少 5 条负例）：
**只出有答案的题，会奖励"乱编"。** 一个爱编答案的系统在全是正例的评测集上分数会很高 —— 因为它 100% 都"答了"，
而正确答案可能只是碰巧蒙对。负例专门抓这种行为。

**正确行为**：明确说资料里没有 / 无法回答，**不是**硬给一个答案。

**类比（前端视角）**：像单测里必须写"**非法输入应当报错**"的用例。
只测正常流程的单测，会让"永远返回成功"的实现拿满分。

**⚠️ 本项目 Q3 的关键结论（分母问题）**：
如果把负例**剔出分母**、只统计"答了的题"，分母就**随系统行为浮动** ——
A 配置拒答了 3 条、C 配置拒答了 1 条，两个配置的分母就不同，**百分比不可比**。
（同 §1 前提 2。）

## §6 噪声地板（ε）/ 抖动（variance）

**中文名**：噪声地板 / 抖动 / 翻转率
**一句话定义**：**同一个输入，重复测量得到不同结论的比例 —— 也就是"这台仪器最小能分辨多大的差异"。**

**为什么它是 D20 的核心**：消融测的是 Δ（§1），但 **Δ 能不能信，取决于 ε**。
如果"差 4 条题"本来就是 judge 自己抖出来的，那"提升 10%"这个结论不成立。
**只看 Δ 不看 ε，等于用一把刻度乱跳的尺子量长度。**

**本项目的算法**：

```
ε = 单次判定与"多数投票真值"不一致的比例
噪声地板 = 50 × 2ε(1−ε) 条  ± 2σ
```

含义：**50 条题里，差几条才算真差异。** 差得比这个少，就还在噪声范围内，不能下结论。

**类比（前端视角）**：像 benchmark 的 `±` 误差条。`1200ms ± 50ms` 和 `1220ms ± 50ms` **没有区别**，
报告里只写 `1200 vs 1220` 就是在骗自己。

**⚠️ 第一轮踩的坑**：ε 算出来是 **0.0000**，但**不能用** —— 因为阈值带是空的（§4），
翻转概率被**结构性地锁死为 0**。所以第 2 轮必须加**难度梯度样本 G1~G7**，把样本打进 4 分附近，ε 才有意义。

**顺序教训**：**先看 judge 动用了哪些档、阈值带占多少，再看 ε。**
第 1 轮就是顺序反了（先算 ε，才发现阈值带是空的）。

## §7 judge 的四个已知偏差

| 偏差 | 英文 | 一句话 |
|---|---|---|
| **自我偏好** | self-preference bias | judge 倾向于给自己（或同族模型）生成的答案打高分 |
| **位置偏好** | position bias | pairwise 时，倾向于选排在前面的那条（所以要**交换位置跑两遍**） |
| **啰嗦偏好** | verbosity bias | 倾向于给**更长**的答案更高分，即使长的那条没更准 |
| **松紧偏好** | leniency / severity bias | 有的 judge 系统性偏松、有的系统性偏严 |

**本项目 Q2 的关键分辨**：self-preference 的作用**分两层**，必须说清在哪一层生效：

- 若三配置**都用同一个 judge** 打分 → 该偏差对 A/B/C **同向同量** → **不影响相对结论（Δ 仍可信）**，只影响**绝对分**
- 若不同配置用了**不同的 judge**（例如网关静默降级切了通道）→ **相对结论也失真**

⚠️ 前提是"**该偏差对三配置同向同量**"。self-preference 通常同向，但 **verbosity 不一定同向**
（重排后的答案可能更短）→ 这条要单独验。

**工程后果**：网关的 `_call_with_failover` 是"主通道失败 → 静默切备用"。
judge 若走它，会出现"**部分样本 DeepSeek 打、部分中转 GPT 打**"，而报告只写一个 judge 名 → **抖动测量被污染**。
→ 探针已按「**显式锁通道、失败不降级**」实现。

## §8 其他两个基础词

**ground truth（真值 / 参考答案）**
评测集里**人工写好的标准答案**。judge 判分时的对照物。⚠️ 它本身也可能有错 —— 所以它叫"参考"，不叫"真理"。

**baseline（基准线 / 对照组）**
比较的起点。本项目里 **A 配置（pure_vector）** 就是 baseline。
**没有 baseline 的"提升了"是没有意义的** —— "提升了 30%"必须先说清"相对谁"。
