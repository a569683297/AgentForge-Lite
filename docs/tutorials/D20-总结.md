### 2.1 LLM-as-judge ★

**中文名**：用大模型当裁判 / 大模型即评审
**出处**：2023 年 MT-Bench / Chatbot Arena 那篇论文（Zheng et al., arXiv:2306.05685）推广开。论文报的量级是"GPT-4 当裁判与人类偏好的一致率 **>80%**，与人与人之间的一致率相当" —— **这两个数是引用值，不是本项目实测**。

**一句话定义**：**不用人工、也不用字符串比对，而是再找一个 LLM 读「题目 + 参考答案 + 被测答案（+ 检索片段）」，逐维度给分和理由**，拿它打的分当评测数据。

**为什么非得有它**：RAG 的回答是自然语言，传统两条路都不通 ——

| 老办法 | 为什么不通 |
|---|---|
| **字符串精确匹配**（EM / BLEU / ROUGE） | 参考答案和模型答案**不可能逐字相同**。"年假 5 天" vs "员工每年可休 5 天年假" 意思一样、字面完全不同，会被判**错** |
| **人工逐条打分** | 规模先崩：50 题 × 3 配置 × 3 维度 = **450 次评分**；而且人也有偏差、不可复现、进不了 CI |

**三种用法（看到这个词时要能分辨）**：

| 用法 | 做什么 | 备注 |
|---|---|---|
| **pointwise** | 给**一条**答案打分 | **本项目用这种**（rubric 0–5） |
| **pairwise** | 给**两条**答案判"哪个更好" | MT-Bench 榜用这种；**位置偏差在这儿最凶**，所以绕开 |
| **reference-based** | 拿参考答案判"是否等价" | correctness 维度用的就是这种 |

**它长什么样（入口 → 步骤 → 返回）**

```
入口：(问题, 参考答案, 检索到的片段, 系统生成的答案) + rubric
步骤：① 拼 judge prompt（含 rubric + 要求输出 JSON）  ② 调 judge 模型（temperature=0）
      ③ 解析 JSON → correctness / faithfulness / completeness 三个分
返回：三个 0~5 的整数分
```

**两个类比**（共享同一个性质）：

1. **像测试里的断言**。测一个摘要接口写不出 `expect(summary).toBe("...")`，只能写 `expect(await judge(summary)).toBe("good")`。
   → **judge 就是被测系统在这套测试里的断言**，只不过这个断言本身是**概率性**的。
2. **像类型检查器**。编译器不执行代码，它读代码判断"合不合规格"，给"诊断 + 原因"。
   → judge 是**自然语言输出的类型检查器**。

两个类比的共同点就是它的本质：**它不执行、只判断，而且会误报漏报。**

**⚠️ 关键认知：judge 是一台"有误差的测量仪器"，不是标准答案。**
它的分数是**测量值**、带噪声；噪声决定了你能分辨多小的差异（§5）。**先量尺子，再量东西。**

### 2.2 rubric

**中文名**：评分细则 / 评分量表
**出处**：教育评估领域的标准词，被 LLM 评测直接沿用。

**一句话定义**：**把"好"和"不好"拆成可操作的档位判据，让不同次、不同模型的打分有同一把尺子。**

少了它，judge 每次松紧都不一样 → 同一份答案今天 5 分明天 3 分。**类比：它相当于接口的 contract / schema**，没有它就不是打分，是"随便给个印象"。

**本项目第 2 轮的 rubric（correctness 维度节选）**：

| 档位 | 判据 |
|---|---|
| 5 | 关键事实全部正确且表述完整 |
| **4** | **关键事实正确，但 (a) 表述简略/啰嗦 或 (b) 附带不冲突的常识补充** |
| 3 | 关键事实部分正确 |
| **1** | **与参考答案明确冲突（给出不同关键数值）** |
| 0 | **完全没回答该问题**（跑题 / 纯空话 / 无实质内容） |

**类比（前端视角）**：像把 ESLint 的 `error` 规则从"代码不好"写成具体条目。规则越模糊，不同人跑出来的差异越大。**rubric 就是 judge 的 lint 规则表。**

### 2.3 二值化

**中文名**：二值化 / 阈值化
**一句话定义**：**把连续或多档的分数，按一个阈值压成"是 / 否"，以便算出"答对率"这种百分比。**

**本项目口径**：`correctness ≥ 4` 记为"答对"，否则"答错"。

**为什么不用平均分**：三个维度各 0–5 分，报"平均分 3.72 vs 3.85"是在比较两个小数第二位的差异 —— 而 judge 自身抖动可能就有 ±0.3。**二值化把连续分变成"对/错"，指标才稳定可比较。**

**类比（前端视角）**：像把 Lighthouse 的连续评分（0~100）按 `≥ 90` 判成"通过"。
⚠️ **阈值是人为选的，换一个阈值结论可能就变了** —— 这正是本项目第 1 轮的问题（见 §5.1）。

### 2.4 负例

**中文名**：负例 / 反例 / 拒答题
**出处**：机器学习里的正负样本概念，评测集设计沿用。

**一句话定义**：**评测集里那些"答案本来就不存在、正确行为是不回答 / 说不知道"的题。**

**为什么必须放**（PRD 要求 50 条里至少 5 条）：**只出有答案的题，会奖励"乱编"。**
一个爱编答案的系统在全是正例的评测集上分数会很高 —— 因为它 100% 都"答了"。负例专门抓这种行为。

**正确行为**：明确说资料里没有 / 无法回答，**不是**硬给一个答案。

**类比（前端视角）**：像单测里必须写"**非法输入应当报错**"的用例。只测正常流程的单测，会让"永远返回成功"的实现拿满分。

### 2.5 消融（ablation）★

**中文名**：消融实验
**出处**：源自拉丁语 *ablatio*（带走、切除）。医学里的"射频消融术"就是同一词 —— 把异常传导通路烧掉。

**一句话定义**：**把系统里的某个部件拿掉，重测一遍，看性能掉多少。掉掉的那部分，就是这个部件的净贡献。**

这层含义的学名是 **归因（attribution）** —— 把一个总效果拆到各个部件头上。

**类比（前端视角）**：你给打包产物做了三项优化（代码分割 + tree-shaking + 并行压缩），体积从 1.2 MB 降到 0.7 MB。
但**是哪一项贡献的？** 想回答就得**一次只关一项**，分别构建、比较体积。
**如果你一把全开、一把全关，你只知道总效果，永远不知道谁在起作用。**

**两种等价写法（别被名字绕晕）**：

| 写法 | 做法 | 叙事方向 |
|---|---|---|
| **移除式**（经典消融） | 从最全的 C 出发逐个拿掉：C → B → A | 看"掉"多少 |
| **叠加式**（增量） | 从 A 出发逐个加上：A → B → C | 看"涨"多少 |

**两者的 Δ 完全一样**，只是叙述方向相反。本项目 A / B / C **并列跑**，等价于叠加式的三档。

### 2.6 ε（噪声地板）/ 阈值带 / 难度梯度

**ε 的中文名**：噪声地板 / 抖动 / 翻转率
**ε 的一句话定义**：**同一个输入，重复测量得到不同结论的比例 —— 也就是"这台仪器最小能分辨多大的差异"。**

**为什么它是今天最关键的词**：消融测的是 Δ，但 **Δ 能不能信取决于 ε**。
如果"差 4 条题"本来就是 judge 自己抖出来的，那"提升 10%"这个结论不成立。
**只看 Δ 不看 ε，等于用一把刻度乱跳的尺子量长度。**

**本项目的算法**：

```
ε = 单次判定与"多数投票真值"不一致的比例
噪声地板 = 50 × 2ε(1−ε) 条     （纯噪声期望制造出的差异条数）
判定门槛 = 地板 + 2σ            （超过它才算"可能不是噪声"）
```

**类比（前端视角）**：像 benchmark 的 `±` 误差条。`1200ms ± 50ms` 和 `1220ms ± 50ms` **没有区别**，报告里只写 `1200 vs 1220` 就是在骗自己。

**阈值带（3.5 ~ 4.5）**：二值化阈值 `≥4` 两侧的"危险区"。**只有落在这一带的样本才可能翻转**；
样本全在 5 分或 ≤3 分时，**翻转概率被结构性地锁死为 0** —— 与 judge 稳不稳**无关**（§5.1）。

**难度梯度样本**：为了把样本**打进**阈值带，构造"同一条内容、质量从完整正确逐档降到完全错"的一组答案。
**判据**：标签是人贴的、分是 judge 打的 —— 给现成样本贴"边界"标签没用，必须**把答案本身改到"接近对但不完全对"**。

**顺序教训（重要）**：**先看 judge 动用了哪些档、阈值带占多少，再看 ε。** 第 1 轮就是顺序反了。

### 2.7 另外两个基础词

**ground truth（真值 / 参考答案）**：评测集里**人工写好的标准答案**，judge 判分时的对照物。
⚠️ 它本身也可能有错 —— 所以它叫"参考"，不叫"真理"。

**baseline（基准线 / 对照组）**：比较的起点。本项目里 **A 配置（pure_vector）** 就是 baseline。
**没有 baseline 的"提升了"没有意义** —— "提升了 30%"必须先说清"相对谁"。

### 2.8 judge 的四个已知偏差

| 偏差 | 英文 | 一句话 |
|---|---|---|
| **自我偏好** | self-preference bias | judge 倾向于给自己（或同族模型）生成的答案打高分 |
| **位置偏好** | position bias | pairwise 时倾向选排在前面的那条（所以要**交换位置跑两遍**） |
| **啰嗦偏好** | verbosity bias | 倾向给**更长**的答案更高分，即使长的那条没更准 |
| **松紧偏好** | leniency / severity bias | 有的 judge 系统性偏松、有的系统性偏严 |

缓解手段：**rubric 写细**（自由度越小抖动越小）、**答案长度不计分写进 rubric**、**避开 pairwise**、**judge 不与被评模型同族**。

## §3 评测要回答三个层次完全不同的问题

| 层次 | 问题 | 靠什么答 | 缺了会怎样 |
|---|---|---|---|
| **① 相对** | C 比 A 好吗？好多少？ | 同一评测集跑三配置 | 无法回答"重排有没有用" |
| **② 绝对** | 88% 这条线过了吗？ | judge 打分 + 二值化 | 可能"三配置都很差，但 C 比 A 好 10%" |
| **③ 归因** | 差在哪类题、哪个维度？ | `eval_case_results` 逐条明细 | 只知道"分数低"，**不知道为什么** |

第三层是 v4.1 专门补的（F7.10）：`eval_runs` 只有汇总分，而**汇总分不可再下钻**；
报告要求"失败案例各取 3 条"，没有明细表根本取不出来。

> 与 D19 的 `retriever` 字段是**同一条思路**：结论必须**可归因**。
> D19 问"这条结果是重排产的还是降级来的"，D20 问"这次失分是 A 类还是 C 类、是正确性还是忠实度"。
> **面试可讲的版本：没有归因能力的指标不是指标，只是分数。**

## §4 评测集设计（D21 的直接输入）

PRD F7.1 定死了分布：

| 类别 | 条数 | 测什么 | 典型的失败模式 |
|---|---|---|---|
| **A 文档问答** | 30（**含 5 条负例**） | 单文档召回 + 答案忠实度 | 召回到错片段 → 答得流利但错 |
| **B 跨文档推理** | 10 | 多跳聚合（需要 2 篇以上） | **召回不足就是硬失败**（不是"答得不好"，是"根本答不出"） |
| **C 工具调用** | 10 | 工具选择 + 参数构造 | 选错工具 / 参数幻觉 |

三类**难度不同、失败机制不同**，所以必须**分类别出分**（§6.2 纪律 4）。

### 三条设计纪律（比条数更重要）

**① 必须有负例，而且负例的"正确"是拒答。** 它的作用只有一个：**测幻觉控制**。
如果一个系统对负例也照样编一段，它就是不可用的 —— 而这件事**只有负例能测出来**。

**② 评测集必须先于实现冻结，且不能拿来调参。**
如果写完评测集、看一眼哪条挂了就去改 prompt / 改 `RERANK_CANDIDATE_K`，再重跑 —— 那不是"提升了效果"，
是**把评测集背下来了**（文献里叫**数据泄漏 / 过拟合评测集**）。
规矩是：**评测集冻结 → 跑 → 看结果 → 改代码 → 用同一份再跑**；若"针对挂掉的题"改，要在报告里如实标注。

**③ 题要有区分度。** 全对的题和全错的题，区分度都是 0，都不提供信息。
**50 条里如果 40 条三配置都答对，这次消融实验基本白跑** —— 这个风险 PRD §13 风险表自己承认了
（"评测集质量影响可信度：中→高"）。

> 📌 **前置墙**：库里现在只有 1 篇文档 / 3 个切片。B 类跨文档题需要 ≥2 篇有语义关联的文档 → **D21 前必须先立真实语料**。

## §5 ★今天最有价值的产出：噪声门槛有了实数

### 5.1 先修量具，再量东西

**第 1 轮的 ε = 0 是个假数。** 证据是一条硬事实：

```
judge 实际用到的档位 = { 0, 2, 3, 5 }
                        ↑ 没有 1    ↑ 没有 4
二值化阈值 = correctness ≥ 4
```

**没有任何一条样本落在 4 分附近** —— 要么 5（远高于阈值），要么 ≤3（远低于阈值）。
**阈值带（3.5~4.5）是空的** → 单次判定翻转的概率**必然为 0**，跟 judge 稳不稳一点关系都没有。

> 这与 D18「拿 12 token 的句子测出 2.8 ms」是**同一族错误**：**测量对象选错，得到一个看似精确实则荒谬的数。**

第 2 轮三处修正后，量具合格：

| | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 4 分档样本数 | **0** | **12**（deepseek）/ **17**（relay） |
| 全程空置分档 | 1 分、4 分 | **无** |
| 阈值带占比 | **0%（结构性锁死）** | **16.2% / 21.0%** |
| **ε** | **0.0000（假数）** | **0.0095 / 0.0190** |
| **判定门槛** | **0.00 条（不可用）** | **2.9 / 4.6 条** |

**1 分档的复活同样重要**：B1 / G6 这类"给出了不同的关键数值"（答 20 天，参考是 5 天），
第 1 轮一律被压到 0 分；rubric 写清 `0 = 完全没回答` 与 `1 = 与参考答案明确冲突` 的分界后，它们落到 1 分 ——
**"错得多离谱"这个区分度被找回来了。**

### 5.2 门槛表（50 条题规模）

| 指标 | **deepseek** | **relay-gpt** |
|---|---|---|
| ε（单次判定不一致率） | **0.95%** | **1.90%** |
| ε 的 95% Wilson 区间 | 0.17% ~ **5.20%** | 0.52% ~ **6.68%** |
| 纯噪声期望差异 | 0.94 条 | 1.87 条 |
| **判定门槛（地板 + 2σ）** | **≤ 2.9 条** | **≤ 4.6 条** |

**三个必须跟着数字一起读的限定**：

1. **区间比点估计诚实得多。** 105 次里只有 1~2 次不一致 → ε 的点估计**极不稳**，deepseek 的 Wilson 上限是点估计的 **5.5 倍**。**报 ε 必须连区间一起报。**
2. **真值取自同一批 5 次**（多数投票），所以 ε 被**略微低估**（乐观）→ 真实门槛只会更高。
3. **ε 是在这 21 份样本上量的** → 真实评测集若更简单，阈值带样本更少 → ε 更小、门槛偏低。**换评测集必须重测。**

### 5.3 拿它对照 PRD 的验收线

PRD §13.2 的 S2 验收点：**"混合+重排 vs 纯向量 ≥ +10%"**。
50 条题上，**+10% 相对提升 ≈ 4 条题**（80% → 88%，即 40 条 → 44 条）。

| ε 取值 | 单次判定门槛 | **3 次多数投票后的门槛** |
|---|---|---|
| deepseek 点估计 0.95% | 2.9 条 | **0.36 条** |
| deepseek Wilson 上限 5.20% | 9.1 条 | **2.5 条** |
| relay 点估计 1.90% | 4.5 条 | **0.76 条** |
| relay Wilson 上限 6.68% | 10.9 条 | **3.5 条** |

> 3 次多数投票的算法：判错需要 ≥2 次错 → `P = 3ε²(1−ε) + ε³`；再套 `p = 2P(1−P)`、`地板 = 50p`、`门槛 = 地板 + 2σ`。

**四条读法**：

- **deepseek 单次**：4 条 vs 门槛 2.9 条 → **勉强过线**，只有 1.1 条余量，换个评测集就可能不够
- **deepseek 3 次**：门槛降到 0.36 条 → **轻松过线**，即使按 Wilson 上限也只有 2.5 条
- **relay 单次**：按点估计 4.5 条 → **4 条判不出来**；按上限 10.9 条 → **差得远**
- **relay 3 次**：按上限仍有 3.5 条 → **勉强可判**

> ✅ **"要不要 3 次重复"这个问题，数据给了确定答案：要。** 它把"恰好卡在噪声边缘"变成"余量充足"，
> 而且**在 Wilson 上限这种保守口径下依然成立**。代价是 judge 成本 ×3（**生成侧不用 ×3**，重复的只是打分）。

### 5.4 ⚠️ 这个推算有一条不敢保证的前提

3 次多数投票能降噪，**前提是各次判定的误差相互独立**。
但同一模型对同一份答案往往有**系统性偏好**（这答案它就是不顺眼，5 次全判错）——
这类误差**投票救不了**，因为它每次都往同一个方向偏。

本轮实测**无法**验证独立性（每份样本只有 5 次，且真值本身就取自这 5 次）。
→ 上面"0.36 / 0.76 条"应视为**乐观下限**，真实门槛介于它与单次门槛之间。
**验证方法**（同一份答案 × 2 个温度 × 多次，看误差是否同向）→ **列入 D21 待办**。

### 5.5 分数级抖动 ≫ 二值翻转

| 指标 | deepseek | relay-gpt |
|---|---|---|
| 分数级抖动（出现过多个 correctness 档） | **2 / 21** | **3 / 21** |
| 二值翻转（真正跨过阈值的） | 1 / 21 | 1 / 21 |
| 倍数 | 2.0× | 3.0× |

典型样本（同一份答案，5 次之内）：

- `C2`（boundary）deepseek：`corr=[2,2,4,2,2]` —— **4 就出现过一次**
- `G4`（gradient）deepseek：`corr=[5,5,4,5,5]`、`faith=[4,4,3,4,4]` —— 不跨阈值，但分数在动
- `B4`（easy_bad）relay：`faith=[5,5,5,0,5]` —— **忠实度出现 0 的离群值**

**结论：只看翻转率会把 judge 描述成"很稳"。分数级抖动与二值翻转必须并报。**

### 5.6 跨 judge 一致性：90.5%，而分歧全在阈值带

| | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 一致率 | **12/12 = 100%** | **19/21 = 90.5%** |
| 阈值带有样本吗 | ❌ 空 | ✅ 16%~21% |
| 分歧样本 | **0 条**（最可能分歧的 C2/C3 那次调用全失败） | **C2、G5**（**都是阈值带样本**） |

**第 1 轮那个 100% 是假象**：阈值带空 + 两个最可能分歧的样本调用失败，**双重幸存者偏差**。
本轮阈值带填进样本后分歧立刻出现，且**恰好全部落在阈值带里** —— 这是对第 1 轮判断的直接证明。

> 面试可讲的版本：**一致性高不一定是好事，要看"最难的样本有没有被真的测到"。**
> 用一堆 5 分和 0 分的题去比两个 judge，当然一致。

## §6 消融实验：只变一个变量，且必须可归因

### 6.1 三档配置

唯一变化的变量是 `settings.retriever_config`：

| 配置 | 向量检索 | BM25 | RRF 融合 | bge-reranker | 这一档测什么 |
|---|---|---|---|---|---|
| **A** `pure_vector` | ✓ | — | — | — | **基准线**（baseline） |
| **B** `hybrid` | ✓ | ✓ | ✓ | — | **Δ(B−A)** = BM25 + RRF 的净贡献 |
| **C** `hybrid_rerank` | ✓ | ✓ | ✓ | ✓ | **Δ(C−B)** = 重排的净贡献 |

**怎么读这三个数**：

- Δ(B−A) 很小甚至为负 → BM25 那一路没帮上忙（可能语料里专有名词 / 术语不够多）
- Δ(C−B) 很小甚至为负 → **重排是负资产**，那 **759 ms** 净成本该省掉
- **三个数都要报**，不能只报"C 比 A 高"

### 6.2 四条纪律

| # | 纪律 | 违反的后果 |
|---|---|---|
| 1 | **绝不拿评测集调参** | 写完看一眼哪条挂了就改 prompt 再重跑 = 把评测集背下来了（数据泄漏） |
| 2 | **"提升 10%"必须写清是相对还是绝对** | C=88%、A=80%：相对 +10%（达标）、绝对 +8 个百分点（没到）。报哪个是两个故事 |
| 3 | **样本量必须一起报** | 50 条里 1 条 = 2 个百分点。"提升 10%（+5 条题）"比只写"提升 10%"诚实得多 |
| 4 | **分类别出分** | C 类只有 10 条，全崩也只影响总分 20 个百分点，容易被 A 类高分掩盖 |

### 6.3 三个前提，破一个实验就废

1. **只变一个变量** —— 同一份评测集、同一个 judge、同样的二值化规则、**分母一致**，唯一变的是那三个 config。
   这正是 D19 做「检索配置化」的目的：**同一份测试用例要能构建 3 个 build**。
   若直接把重排塞进 `search()`，B 配置会永久消失，"重排到底有没有用"以后再也答不出来。
2. **分母必须一致** —— 探针测出的 relay **失败率在 1%~37% 之间飘**就是活的反例：
   某些配置少算几条题，分母一变，三个百分比**根本不可比**。
3. **Δ 必须显著大于噪声** —— 见 §5。

### 6.4 别和 A/B 测试搞混

| | **消融实验** | **A/B 测试** |
|---|---|---|
| 环境 | 离线、固定评测集 | 线上、真实用户分流 |
| 看什么 | 检索 / 回答**质量指标** | **业务指标**（点击、留存） |
| 目的 | **归因**：是哪个部件带来的提升 | **决策**：新版本要不要全量上线 |

**本项目做的是前者。**

## §7 三条直接决定 D22 怎么写的推论

1. **能用 `assert` 精确判的就别用 judge。**
   C 类工具调用题（选没选对工具、参数对不对）是**可精确校验**的（函数名 + JSON 结构比对）。
   → **A/B 类走 judge，C 类走精确校验**，只有"选对了但措辞难判"的残余才兜给 judge。
   把确定性判定交给 judge 猜，等于**把精确判定换成有噪声的判定**。

2. **judge 必须显式锁通道、失败不降级。**
   网关的 `_call_with_failover` 是"主通道失败 → 静默切备用"。judge 若走它，会出现
   "**一部分样本 deepseek 打、一部分 relay 打**"，而报告只写一个 judge 名 → **抖动测量被污染**，
   测出来的是"后端漂移"而不是"judge 的随机性"。（探针已按这个写，D22 照抄。）

3. **"3 次重复"重复的是 judge，不是生成。** 评测拆两阶段：

   ```
   阶段一：三配置各跑一遍 50 条 → 答案 + 检索结果落库（生成只做 1 次）
   阶段二：对已落库的答案重复打分 3 次 → 取多数
   ```

   若生成也 ×3，成本翻三倍，**还把"生成抖动"混进"judge 抖动"，两个噪声源再也分不开**。

## §8 三问判分要点

| 题 | 考什么 | 要点 |
|---|---|---|
| **Q1** | 相对 vs 绝对口径，以及噪声 | 相对 **+10%** 与绝对 **+8 个百分点** 是**两个数、都要写**；「提升 8%」是**口径混乱**（会被读成相对值）。4 条题的差异**落在抖动范围内 → 不构成显著提升**。⚠️ 用一个口径否掉提升、却留下另一个，是**双标** |
| **Q2** | 偏差在哪一层生效 | 术语是 **self-preference bias**。它**不影响 A/B/C 对比**（三配置共用同一 judge、偏差同向），**只影响绝对分数**（整体偏高 → "88% 过线"的判定被放松）。⚠️ 前提是偏差**同向同量** —— **长度偏差不一定**：若 C 配置更容易产出长答案（重排把长片段排前），就会引入配置间的非等量偏差 |
| **Q3** | 负例与分母 | 致命点不是"有偏差"，而是**分母不同 → 三个分数不在同一把尺子上**：`分母 = 50 − 拒答数`，而 C 召回到更多片段 → 更少拒答 → 分母更小。另外两条：正确拒答被**无偿剔除**（等于删掉一个测试项）；"答了/没答"的判定本身要靠额外规则，引入可钻空子的环节 |

## §9 今天踩的四个坑（都是"不报错但数字错"那一族）

| # | 坑 | 后果 | 修法 |
|---|---|---|---|
| 1 | 样本"我以为的边界"≠ judge 眼里的边界 | ε = 0 假数 | **加难度梯度样本 G1~G7**，把质量谱压进阈值带 |
| 2 | rubric 档位描述笼统 | 1 分 / 4 分档空置 | 三档判据写具体 + 给反例（"答 20 天 vs 参考 5 天"） |
| 3 | **计时起点写在并发锁外面** | "单次耗时"含排队 → deepseek 报成 **11.74s**（真实 **0.84s**，**差 14 倍**） | 拆 `request` / `e2e` 两个口径 + **内置自检**（理论 ÷ 墙钟 ≈ 1，实测 **0.98** ✅） |

> 与 D18「拿 12 token 的句子测出 2.8ms」同族：**量具错了，后面全错。**

## §10 自测题（复习时先合上文件）

1. 评测的三个层次分别是什么？为什么"汇总分不可再下钻"是个问题？
2. 为什么必须有负例？"只在答了的题上算准确率"错在哪（要说出两层）？
3. 为什么 0-5 分要**二值化**、而不是直接报平均分？
4. rubric 里 4 分档的判据写具体，为什么能让 ε 变得可测？
5. 什么是**阈值带**？为什么"阈值带为空时算出的 ε = 0"是假数？
6. 判定门槛 2.9 条是怎么算出来的？（从 ε 到门槛的完整链条）
7. 为什么"3 次多数投票"能降噪，但**不一定**真能降到 0.36 条？
8. 主 judge 为什么选 deepseek 而不是那个中转 GPT？（要说出至少三条数据）

### 答案

**1.** ① 相对（C 比 A 好多少 → 同一评测集跑三配置）② 绝对（88% 这条线过了吗 → judge 打分 + 二值化）
③ 归因（差在哪类题、哪个维度 → `eval_case_results` 逐条明细）。
`eval_runs` 只有汇总分，**汇总分不可再下钻** → PRD 要求报告"失败案例各取 3 条"，取不出来。

**2.** 负例的作用是**测幻觉控制** —— 只出有答案的题会奖励"乱编"，一个 100% 都答的系统在正例集上分数很高。
"只在答了的题上算准确率"错两层：
① **分母不同 → 不可比**：`分母 = 50 − 拒答数`，C 召回到更多片段 → 拒答更少 → 分母更小，三个百分比不在同一把尺子上；
② **正确拒答被无偿剔除**：正确行为拿不到任何加分，等于删掉一个测试项。

**3.** judge 的 0-5 档本身有抖动（±0.3 量级），报两个平均分的小数第二位差异**分不清是真差异还是噪声**。
二值化（`correctness ≥ 4`）把连续分压成对/错，指标才**稳定可比较**。

**4.** 4 分档是**二值化阈值所在的那一档**。判据笼统时 judge 从不给 4 分（第 1 轮 0 条），
阈值带（3.5~4.5）里**没有样本** → 翻转概率被**结构性锁死为 0**，ε 必然是 0（假数）。
把 4 分档判据写具体（"关键事实正确，但表述简略 或 附带不冲突的常识补充"）+ 加梯度样本，样本才会落进去，ε 才可测。

**5.** 阈值带 = 二值化阈值两侧的危险区（本项目 3.5 ~ 4.5）。
**只有落在这一带的样本才可能翻转**；样本全在 5 分或 ≤3 分时，无论 judge 多不稳，翻转概率都是 0 ——
所以那时算出的 ε = 0 反映的是**样本分布**，不是 judge 稳定性。

**6.** 链条：① 同一份答案重复 5 次 → 多数投票当真值 → ② 单次与真值不一致的比例 = **ε**（deepseek 1/105 = **0.95%**）
→ ③ 两个配置各 50 条时，纯噪声期望差异 = `50 × 2ε(1−ε)`（deepseek **0.94 条**）
→ ④ 加上 2σ（σ=0.96）→ **门槛 2.9 条**。含义：差异小于 2.9 条时无法排除是噪声。

**7.** 能降噪是因为"单次判错"要变成"3 次里 ≥2 次判错"，概率从 ε 降到 `3ε²(1−ε)+ε³`（deepseek：0.95% → 0.36 条门槛）。
**但前提是各次误差独立**。同一模型对同一份答案常有**系统性偏好**（5 次全判错），这类**同向偏差投票救不了**。
本轮数据无法验证独立性 → 0.36 条是**乐观下限**，真实门槛介于它与单次门槛之间。

**8.** 三条数据：① **单次 HTTP 往返 0.84s vs 16.46s（19.6×）**；② **105 次墙钟 22.6s vs 602s（26.6×）**，
外推 D23 的 450 次是 **1.6 分钟 vs 43 分钟**；③ **重试次数 0 vs 1**，且 relay 的失败率**在 1%~37% 之间飘**
（同一脚本上一轮 37.1%）—— 比"失败率高"更麻烦的是**不可预测**。
另外：自我偏好在 **A/B/C 对比**里不构成问题（三配置共用同一 judge、偏差同向），所以不构成选它的障碍。
