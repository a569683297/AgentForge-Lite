评测抖动的三层与诊断流程

同一道题跑两遍分数不一样 —— 先判断它属于哪一层，再决定用什么办法。用错工具比不做更糟。
两次结果不一样 → 输入（题 + 语料）的指纹相等吗？ → 不等 = 第 3 层 · 相等 → 看重复的是「打分」还是「跑系统」
第 1 层

裁判侧抖动

同一份答案反复交给裁判模型打分，分数不一样。
被测对象
不变（答案被钉住）
我们在做的事
重复测量同一个值
处理
重复打分 + 多数投票
ε = 0.95%（deepseek 裁判）
95% Wilson 区间 0.17% ~ 5.20%
工具：统计学 —— 有效
第 2 层

生成侧抖动

同一道题、同一配置，重复跑系统，答案本身就是随机变量。
被测对象
每次都不同
我们在做的事
给一个随机变量抽样
处理
只能重复生成，或放大噪声门槛
B01 两次独立运行：459 字判对 / 511 字判错
裁判内部 5 次打分各自完全一致
投票救不了 —— 重复的是裁判，不是输入
第 3 层

不是抖动

两次不同不是因为随机，而是输入被换过：语料改了、题改了、配置串了。
被测对象
偷偷换掉了
特征
重复多少次都不收敛
处理
指纹前置拦截，不做统计
改语料正文 + 不带 force 跑播种脚本：
语料没更新、指纹不变、三处都不出声
最危险 —— 它看起来像抖动

诊断流程：五步定位，再决定改哪里

#动作目的成本
①先冻结 核对两次跑的题指纹 + 语料指纹。不相等 → 第 3 层，立刻停下查输入，不要动统计。 0（纯查库）
②测裁判侧 把第一份答案落库固定，对同一份答案重复打分 M 次。答案钉住了 → 变化只可能来自裁判。 M 次打分
③测生成侧 重复跑 N 次得 N 份答案；每份先打分 M 次取多数（压掉裁判噪声），再比较 N 份的多数结论。 N×M 打分 + N 次生成
④比大小 谁大先解决谁。生成侧 ≫ 裁判侧 → 打分 3 次等于白花钱。 0
⑤定 N 用 ③ 量出的散布反推「消融要生成几次才够」——先量再定，别先花 3 倍钱。 0
这一步最容易犯的三个错
  1. 用统计工具去处理第 3 层。输入被换了却「多跑几次取平均」→ 得到一个混合了两个不同系统的数字，没有任何含义，却看起来更稳。修法：报告生成前强校验指纹，不等就拒绝出报告（不是打一行警告）。
  2. 重复生成 N 次后取最高分。这是选择偏差 —— 挑出运气最好的那次当成系统水平，会系统性虚高，而且恰恰在最不稳定的题上虚高最多。正确做法是取多数结论，并把散布一起报出来。
  3. 把不同口径的门槛并列比较。D20 的「2.9 条」用的是 ε 点估计 0.95%；D21 的「11.42 条」用的是 Wilson 上界 7.14%。不是同一把尺子，放一起会得出「两次测量矛盾」的错误结论。

一句话判据

层你重复的是什么该用什么
第 1 层重复裁判（输入不变）多数投票、置信区间
第 2 层重复输入（裁判固定）抽样取分布，报散布不报最高分
第 3 层什么都没重复 —— 测的是两个东西指纹比对，拒绝出报告
