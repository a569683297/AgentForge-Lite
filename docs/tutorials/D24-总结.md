## §2 核心概念讲解

> ⚠️ 遵守铁律 14：**每个新名词第一次出现时，先在原地给「它是什么、解决什么问题」**，再往下讲。不许堆到文末术语表。

### 2.1 `gold` —— 「标准答案落在哪几篇文档里」

**gold（黄金文档 / 标准答案文档）**：人为标注的「这道题的正确依据在哪几篇文档里」。
在本项目里就是 `eval_cases.doc_ids`（一个 UUID 数组），出题时从 `doc_slugs` 映射过来。

它解决什么问题：**让"检索对不对"变成机器可判**。没有它，你只能靠人眼读每条检索结果；有了它，程序就能自动算出「正确依据排第几」。

**一条必须守死的纪律**（D21 就定的）：
`doc_ids` **只用于判分与统计，绝不参与检索过滤**。
一旦拿它当检索条件，等于**开卷考试还告诉你页码** —— 检索难度归零，A/B/C 三配置的差异被整体抹平，整个评测从根上失效。

> 📌 新名词：**A / B / C 配置** —— 本项目 PRD §9.5 要跑的三条检索链路，用来做消融（ablation）。
> **消融（ablation）**：一次只去掉/换掉一个部件，看成绩变多少，从而判断「这个部件到底有没有用」。
> 这里的三条链路是：
> - **A = `pure_vector`**：只用向量（语义）检索，取 **top5**。
> - **B = `hybrid`**：向量 + BM25（关键词）两路结果用 **RRF** 融合，取 **top5**。
> - **C = `hybrid_rerank`**：融合出 **top20** → 送**重排**模型精排出 **top5**。

> 📌 新名词：**BM25**（Best Matching 25）—— 一个纯字面的关键词打分公式。它算的是「查询里的词在这篇里出现多少次、这个词在全库有多稀有、这篇有多长」。
> 它解决什么问题：向量对**精确字面**不敏感（问「E104 型号」可能给你一堆"意思相近"的片段），BM25 恰好相反 —— 字面不命中就是 0 分。

> 📌 新名词：**RRF**（Reciprocal Rank Fusion，倒数排名融合）—— 把多路检索结果合成一个顺序的方法：**丢掉分数、只看名次**，一篇文档的融合分 = `Σ 1/(60 + 它在该路的名次)`。
> 它解决什么问题：向量的余弦相似度 ∈ [0,1]、BM25 分数无上界，**量纲不同不能直接加权相加**（加权的 α 会变成摆设）。只取名次就同量纲了。

### 2.2 gold 的「名次」是**文档级**的

**名次（rank）**：把检索结果从第 1 条往下数，gold 第一次出现在第几条。

**为什么必须是文档级、不能是切片级**（切片 = chunk，一篇文档被 `split_text` 切成的小段，检索的最小单元）：
一篇文档有 6~7 个切片。如果按切片算名次，`top1`~`top5` 里可能全是**同一篇文档**的不同切片 —— 名次看着很靠前，但对用户毫无意义（他要的是"这篇文档出现了没有"）。
本项目取 **该文档最早出现的那个名次**（`setdefault` 语义），问的是：**用户要往下翻几条，才第一次看到正确依据。**

### 2.3 「题太简单」的精确形式 —— 一张三行表（**全篇最重要**）

`retrieve()` 默认只取 5 条（`DEFAULT_TOP_K = 5`），B 配置取的就是融合序前 5。C 配置的重排窗口是 20（`RERANK_CANDIDATE_K = 20`）。于是 gold 的名次直接决定谁能拿到：

| gold 的融合名次 | 后果 | 能不能分开配置 |
|---|---|---|
| **1 ~ 5** | B 拿到了 → C 顶多把它排得更好看 | **分不开 B / C** |
| **6 ~ 20** | B 拿不到，**C 的窗口是 20，可能救回来** | **唯一能分开 B / C 的区间** |
| **> 20** | 重排窗口之外，**谁都拿不到** | 只是"变难"，不产生任何差异 |

**要分开 A 与 B**（纯向量 vs 融合），还需要另一个条件：
**gold 的「向量路名次 ≥ 6」而「融合路名次 ≤ 5」** —— 即"向量单独做不到、融合补上了"。

> 这就是 D23 说「三层全撞天花板、瓶颈是任务难度」的可操作形式：
> **现在满足 6~20 的题：0 条。** 不是重排没用，是**没有一道题给过它发挥作用的机会**。

### 2.4 剂量-反应（dose-response）

**剂量-反应**：原本是药理学的词 —— 给不同**剂量**（dose），看**反应**（response）怎么变，画出一条曲线。
在本项目里：**剂量 = 加了几篇干扰文档，反应 = gold 的名次被推后多少位。**

**为什么必须做曲线、不能只插一篇**：
一篇 1500 字的干扰文档，与某个问题强相关的通常只有 1~2 条条款对应的切片 —— 所以插一篇最多把 gold 从第 1 名挤到第 2、3 名，**推不出 top5**。
只插一篇，你只能得到一个"不够"的结论，**答不出"那么要几篇"**。而"要几篇"才是乙案真正的成本问题。

### 2.5 干扰文档：**同主题不同结论** vs **近重复**

**干扰文档（distractor）**：故意放进语料、用来把正确文档挤下去的文档。

两种形态，效果完全不同：

| 形态 | 做法 | 挤动哪条路 |
|---|---|---|
| **同主题、不同结论** | 写一篇《子公司差旅费用管理实施细则》，主题词与原文一样、**数字全不同**（住宿 600/450/350 而非 500/400/300） | **向量路**（语义像就够了） |
| **近重复** | 把原文**近乎逐字复制**，只改数字/加一句"已废止" | 向量路 **+ BM25 路**（字面高度重合） |

**为什么这个区别是决定性的**：融合序（B 配置）要一篇文档**被两路共同认可**才能排到前面。
同主题不同结论的干扰篇，语义像（向量路强）但**用词不同**（BM25 路弱）→ 它在融合序里只能抢到第 1 名，**其余的同类干扰篇全排在 gold 之后** → **推力饱和**。

### 2.6 全局副作用：加语料不是「只让目标题变难」

**BM25 的 N 与 avgdl 是「全库量」**：
- `N` = 语料里切片总数
- `avgdl` = 所有切片的平均长度（词数）

BM25 的打分公式里含有 `N` 和 `avgdl`。**加任何一篇文档，这两个数都会变 → 所有查询的 BM25 分数都会漂**，从而改变融合序。
→ 所以「加干扰文档」是一次**全局操作**：它可能把目标题变难，**也可能把别的题变得更容易**。实测里两种方向同时出现了（附录 B.4）。

**推论**：乙案的收益**必须全量报**，不能只盯着目标题那几条 —— 否则报出来的提升里混着"别的题被弄简单了"。

### 2.7 为什么必须记录「干扰篇自己的名次」

这是本探针最容易被漏掉的一步，但**它决定结论该归因给谁**：

| 现象 | 结论 | 后续动作 |
|---|---|---|
| 干扰篇**压根排不上来** | 「干扰篇写得不够像」 | **可修**：把干扰篇写得与 gold 同台，再测 |
| 干扰篇**排上来了**、gold 却纹丝不动 | 「gold 真的很稳」 | **不可修**：换手段 |

只报 gold 名次，这两种情况会**印成同一个数字**。所以本探针每轮都记录干扰篇自己的最好名次。

## §3 代码逐行解读

### 3.1 `scripts/d24_cases_challenge.py` —— 10 条「口语化挑战题」（甲案）

**它解决什么问题**：给「改问法」这条路造一个**唯一变量干净**的对照 —— 同一批答案、同一份语料，只换问法。

**① 核心设计：答案从对照组复制，不手写**（`resolve()`）

```python
"reference": base["reference"],
"evidence": base["evidence"],
"doc_slugs": list(base["doc_slugs"]),
"expected_tool": base.get("expected_tool"),
```

为什么**必须**复制而不是照着抄一遍：
- 手抄 10 条原文依据**必然出错，而且错了不报错**。D21 的 B07 就是活例：引文标错了文档，那题其实不是跨文档题，**B 类成绩全程是假的**。
- 「唯一变量是问法」这句话**必须能被机器证明**。复制过来的字段逐字相同，断言就能钉住；手写只能靠"我记得我抄对了"。

⚠️ `list(...)` 不是多余的：Python 的赋值是**名字绑定不是复制**，不写 `list()` 的话挑战题与对照组会**共享同一个列表对象** —— 今天不出错，但将来谁往里 `append` 一下，对照组跟着变，**且不报错**。这类"定时炸弹"拆掉的成本是零。

**② 为什么 `category` 用 `challenge_qa` 而不是沿用 `doc_qa`**
沿用的话，**旧 A 类均分会被静默拉低**（分母里混进 10 条难题）—— 报告里那个"A 类 88%"就不再是同一个东西了。这是 D23 踩过的「分母悄悄变了」。

**③ 自检断言（5 条不变量）** 其中最关键两条：
- 三字段必须与对照组**逐字相同**
- 提问必须**真的改过**（防"新建了一条题但忘了改问法"，那这个实验就变成对照组自己跟自己比）

并且做了**负测试**验证断言真会失败：篡改 `evidence` ✅ 抓到 · 提问照抄对照组 ✅ 抓到 · 对照组编号写错 ✅ 当场 `KeyError`。

### 3.2 `scripts/d24_rank_probe.py` —— 量 gold 在四条链路上的名次

**① 三个常量故意硬编码、不 import**

```python
B_CONFIG_TOP_K = 5      # = retrieval_service.DEFAULT_TOP_K
RERANK_WINDOW = 20      # = retrieval_service.RERANK_CANDIDATE_K
```

为什么**故意不 import**：探针要**独立于被测代码**。如果 import 了，被测常量将来被改错，探针会跟着错，**"判据"就没有独立来源了**。
代价是改了被测常量探针不会自动跟 —— 所以 `main()` 把两个数印在标题上，一眼能看出不一致。

**② `slug_to_uuid()` —— 列名是回查来的，不是猜的**
`documents` 表**没有 slug 列**（实测 `information_schema`：只有 `id / filename / file_type / status / chunk_count / error_message / created_at`）。第一版写成 `d.doc_slug` 直接 `UndefinedColumn`。slug 是出题侧的业务标识，得靠 `SLUG_TO_FILENAME` 反查文件名。

**③ `gold_rank()` —— 文档级 + 取最早名次**
见 §2.2。两个决定都在这里落地。

**④ `measure()` —— 四条链路各自独立跑一遍、不复用**
复用会让"某条链路其实没跑到"看不出来，而本探针的**全部价值**就在于区分"哪条链路把它排到哪"。单链路失败记 `{label}_err` 而不中断整轮。

**⑤ `verdict()` / `ab_contrast()` —— 标签全部由名次算出**
禁止硬编码（铁律 11）。`ab_contrast()` 我修过一个**必须记住的 bug**：

```python
# 第一版（错）：只判了一个方向
if vec > 5 and fused <= 5:  return "能分开 A/B"
if vec <= 5:                return "向量已达到"
```

D24 那条题是**反的**（向量第 3 名中、融合第 8 名不中），却被印成「向量已达到」—— **一条真区分被当成没区分**。
**为什么错得看不出来**：漏掉的那一半印出来的是**一个听起来完全正常、甚至像好消息的标签**。要是它印成 `ERROR` 或 `None`，当场就发现了。
→ 改成四象限：`A 中 B 不中` / `B 中 A 不中` / `都中` / `都不中`。
**"能不能分开"是对称的，只判一个方向 = 把一半答案丢掉，而丢掉的那半在输出里长得像"没问题"。**

### 3.3 `scripts/d24_distractor_probe.py` —— 干扰文档探针（乙案去风险，本轮重点）

**它做什么**：临时往共享语料插入 1~4 篇「同主题、不同结论」的文档，每插一篇量一次 gold 名次，最后**撤干净并自证恢复**。

#### ① `TWINS` —— 干扰篇正文的三条设计规则（都能机检）

```python
#   ① 同主题词：必须出现「差旅费用 / 住宿费标准 / 伙食补助 / 报销申请 / 交通工具」
#   ② 不同结论：住宿限额、补助标准、报销时限、审批金额全部与 gold 不同
#   ③ 体量与形态接近：13~14 条条款、1400~1700 字
```

三条各解决一个问题：
- 违反 ① → "同主题"只是我自己说的，干扰篇根本没资格竞争；
- 违反 ② → 干扰篇被检索到也不会改变答案，**造不出失败模式**；
- 违反 ③ → 切片数差异会让"挤进前 5 的能力"**不可比**。

#### ② 入库必须走**生产同一条路径**

```python
_doc_id, n_chunks = await document_service.ingest_texts(
    ["\n".join(clauses)], filename=filename
)
```

关键在**形态与 `scripts/d21_seed.py` 逐字相同**：`ingest_texts([full_text(lines)], filename=...)` —— **单段文本**，靠 `_split_segments → split_text` 切。
手写 INSERT 会造出一个**切片边界与真实语料不同的假文档**，测出来的名次不可比。

#### ③ `probe_uuid()` —— 按前缀**现查**，不靠入库返回值

```python
rows = await conn.execute(text(
    "select id, filename from documents where filename like :p escape '\\'"),
    {"p": PROBE_PREFIX + "%"})
```

为什么不直接用 `ingest_texts()` 的返回值：那个返回值只在"本轮插入成功"时才存在。
**现在查库**能同时覆盖"上一轮没清干净"的情况 —— 于是"有残留"会当场表现为"识别到的干扰篇数比预期多"，而不是悄悄少算。

#### ④ `ranks_for()` / `worst()` / `best_of()`

- `ranks_for(hits, chunk2doc, wanted)`：返回 `{文档 UUID: 最早名次}`，只含 wanted 里的文档。
- `best_of()`：第一篇 gold 的名次 —— 回答"翻几条能看到**至少一篇**依据"。
- `worst()`：**最差**那篇 gold 的名次 —— 回答"**所有**依据都拿到要翻几条"。

**为什么两个都要报**：跨文档题（B 类）要**两篇都拿到才算答得全**。只报最好那篇，会把"另一篇已经掉出窗口"藏起来。
`worst()` 对 `ranks is None`（整条链路报错）返回 `k+1`（窗口外）而不是崩掉 —— 一条链路挂掉不该让整轮没有结论，但它**会在 ⑤ 自检段被单独列出来**，所以不会被当成正常结果。

#### ⑤ `zone()` —— 区间由数据算出来

```python
def zone(rank: int, k: int) -> str:
    if rank <= DEFAULT_TOP_K:      return f"1~{DEFAULT_TOP_K}"
    if rank <= k:                  return f"{DEFAULT_TOP_K + 1}~{k}"
    return f">{k}"
```

三个区间就是 §2.3 那张三行表。写成函数、写在**一处**，是为了避免"表头写一个口径、结论按另一个口径说"。

#### ⑥ 写入窗口与 `finally`

```python
if args.dry_run:
    print("\n--dry-run：跳过插入与清理（库里一个字节都没动）")
else:
    try:
        for i in range(rounds):  ...插入...  ...测量...
    finally:
        removed = await document_service.delete_documents_by_prefix(PROBE_PREFIX)
```

三件事：
- **`--dry-run` 先跑**：只量基线、不写库 —— 用来验证链路与指纹，确认无误**才**进写入窗口（而不是"先插进去看看"）。
- **`try/finally`**：即使中途异常也撤干净。
- **`delete_documents_by_prefix(PROBE_PREFIX)`**：共享库上的清理必须**按前缀自限**（铁律 12 附则二），绝不用 `delete_all_documents()` —— 那会把 8 篇长期语料一起删掉，而且**完全静默**。

#### ⑦ 自证恢复（三条断言 + **指纹**）

```python
residue = await document_service.count_documents_by_prefix(PROBE_PREFIX)
fp_after, chunks_after = await eval_service.corpus_fingerprint_from_db(None)
restored = (residue == 0 and docs_after == docs_before
            and chunks_after == chunks_before and fp_after == fp_before)
...
assert restored, "语料未逐字恢复 —— 后续结论作废。"
```

**为什么只打印「已删除 4 篇」不算证据**：
"删了 N 篇"只说明**我调用了删除**，不说明**库回到了原样**。
**语料指纹（corpus fingerprint）是"整份语料内容 + 切片方式的 sha256"** —— 它逐字相同，等于"语料已逐字恢复，连切片顺序都一样"。这是比计数强得多的证据。

⚠️ **指纹在这里有个副作用必须知道**：`corpus_fingerprint_from_db(None)` 传 `None` = **全库**（D22 的设计：检索是在整个知识库上做的，别的脚本的残留同样会被命中）。
→ 所以**插入期间指纹会变**。这个窗口里若有别的会话在跑评测，它会记录到错误指纹 / `d22_verify` 会红。**本脚本因此把写入窗口压到最短**（插入与清理在同一次运行里完成）。

⚠️ 还有个配套设计：脚本**开跑前先比对指纹**，与 D23 记录的 `5783a666…` 不符就**拒绝出结论**（除非 `--force`）——
因为"插入前"的基线已经不是 D23 那个语料了，名次变化**无法归因**到干扰篇。

#### ⑧ `assert`（自检）放在**最后一行**

```python
await engine.dispose()
assert restored, "..."
```

**为什么把硬失败放最后**：先让上面的报告完整打出来（否则你不知道少了什么就被中断了），**再用退出码把「这批结论作废」变成不可忽略的事实**。
只在屏幕中间印一行"⚠ 恢复失败"等于没发生 —— 这正是铁律 12 的「静默失效」。

#### ⑨ ⑥ 关键读数段为什么单独存在

```python
rows_read.append((c["case_key"], vecs, fuses))
mono_vec = sum(1 for _, v, _ in rows_read if all(b >= a for a, b in zip(v, v[1:])))
```

上面的 ② 表是**原始数据**，结论要用的位移量、单调性、临界名单必须**由代码算**出来。
**手抄数字进结论 = 铁律 11 的老坑**（数据反了、文字照念，D13/D16/D18 连中三次）。所以位移、单调、临界全部现算。

## §5 面试考点

**Q：你怎么证明"检索评估里配置没差异"不是因为评估器坏了？**
A：分三层排除。① 检索层：加随机基线做负对照 —— 随机撞上一个**非 gold** 文档落进 top5 的概率只有 4.5%~9.4%，而真实 gold 的 `Hit@5` 是 100%，说明指标有效。② 裁判层：读 judge 的**原始理由**而不是汇总分，发现失败是**评测集缺陷造成的假失败**（`reference` 写成给评测人的元说明）并修掉。③ 生成层：实测抖动。三层都排除后，剩下的解释是**任务难度**。

**Q：那"任务难度不够"你怎么证明，而不是靠感觉？**
A：把它变成一个**名次区间**。B 配置取融合序 5 条、C 配置重排窗口 20 条，所以 gold 名次落在 **6~20** 才是唯一能分开 B/C 的区间；`>20` 谁都拿不到、`1~5` 谁都拿得到。实测这个区间里的题是 **0 条** —— 不是重排没用，是没给过它机会。

**Q：你说"加干扰文档有用/没用"，怎么测的？**
A：做**剂量-反应**：逐篇追加 1→4 篇同主题不同结论的文档，每篇量一次 gold 名次。结论**分链路**：
- 向量路平均被推后 **1.25 位**（8/8 条单调不减，A08 精确是 1→2→3→4→5）；
- 融合路平均只有 **0.38 位**，且**饱和**（各题停在 2~3 名不动）；
- 重排路 **35/35 条全部仍在 top5**，四轮纹丝不动。
→ 所以这条路的产出是 **A vs B/C 的区分**，不是 B vs C 的区分。

**Q：为什么融合路推不动？**
A：RRF 奖励"**被两路共同认可**"。同主题不同结论的干扰篇**语义像但用词不同** —— 向量路强、BM25 路弱，所以在融合序里只能抢到第 1 名，其余同类干扰篇全排在 gold 之后 → 推力饱和。**要让融合路也动，干扰篇必须同时在 BM25 路上压过 gold，也就是要"近乎逐字重复"。**

**Q：加文档有没有副作用？**
A：有，而且是**双向的**。BM25 的 `N`（切片总数）和 `avgdl`（平均长度）是**全库量**，加任何一篇都会让所有查询的 BM25 分数漂。实测：向量路有 2 条题从 1~5 掉进 6~20，同时融合路有 1 条跨文档题**从 6~20 升进 1~5**。→ 所以这类实验的收益**必须全量报**。

**Q：你怎么保证实验没有污染共享环境？**
A：四道：① 所有临时文档带固定前缀，清理**按前缀自限**；② `try/finally` 保证异常也撤干净；③ 结束时断言"残留 0 + 文档数恢复 + 切片数恢复 + **语料指纹逐字相同**"；④ 硬失败用**退出码**表达（assert 放最后），不靠屏幕中间一行警告。

## §7 踩坑记录

| # | 坑 | 机制 | 修法 |
|---|---|---|---|
| 1 | `ab_contrast()` **只判一个方向** | 漏掉的那一半印成"向量已达到"——看起来像好消息，所以没人会去查 | 四象限判据；**"能不能分开"是对称的** |
| 2 | 列名猜错（`d.doc_slug`） | `documents` 表**没有** slug 列 → `UndefinedColumn` | 回查 `information_schema`，不按印象写列名 |
| 3 | 交付/讲解里的 ASCII 引号混进中文串 | Python 串里出现裸 `"` → `SyntaxError`；而**同一类错连犯 4 次**（每次都只在语法检查时才暴露） | 写完**立刻** `ast.parse` 复查；中文串内一律用「」 |
| 4 | 结论段写死一句话，覆盖不到"分链路"这个事实 | 初版结论只看"区间变了没有"，得出"干扰篇有效 1/8"——**而那条实际是变好** | 结论**分链路**由数据算；这也是铁律 11「结论必须由数据驱动」的第 N 次命中 |
| 5 | 探针 ② 表里的数字**差点被手抄进结论** | 位移量/单调性/临界名单如果手抄，等于埋一个"数据变、文字不变"的雷 | 新增 ⑥ 段，全部**由代码算** |
| 6 | 写入窗口期间**全库指纹会变**（`corpus_fingerprint_from_db(None)` 是全库） | 别的会话在此期间跑评测 → 记录到错误指纹 / `d22_verify` 会红 | 窗口压到最短（插入+清理同一次运行）；跑前先比对指纹，不符就拒绝出结论 |
| 7 | 清理"调了函数"不等于"库回到原样" | "已删除 4 篇"只证明**我调用了删除** | 用**语料指纹逐字相同**做证据；并独立回库再查一遍（文档数/切片数/残留） |

## 附录 C：结论与下一步

### C.1 三条结论

1. **甲案（改问法）无效**：10 条里 9 条 gold 仍第 1 名。语义嵌入对口语化改写几乎免疫 → **竞争必须在语料侧造**。
2. **乙案模拟（加干扰文档）方向对、但链路口不对**：
   - 干扰篇**确实能挤进 top5**（6/8 条目标题）；
   - 但它**只推得动向量路**（平均 1.25 位，8/8 单调），**推不动融合路**（平均 0.38 位，饱和），**完全推不动重排路**（35/35 全在 top5）。
   - → 这条路产出的是 **A vs B/C 的区分**，**不是** B vs C 的区分。
3. **`N` / `avgdl` 是全库量 → 加语料是全局操作**，方向不定：本次同时出现"2 条变难"和"1 条变易"。→ 收益必须**全量报**。
