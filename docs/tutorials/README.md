# 教程编号对照表

本目录里的 `DXX` 是**教程执行编号**，与 `docs/PRD-v4.1-含前沿技术.md` §13.2
里程碑表里的**规划编号**（也是 D 开头）**不是同一套**。同一个字母 D，两套数，
混着读必错 —— 这份表就是用来对账的。

## 为什么会有两套号

历史上发生过两次「一天做两天的事」+ 一次跳号 + 一次补账：

| 事件 | 影响 |
|---|---|
| 教程 D01 覆盖规划 D1+D2（脚手架 + 分层目录合并） | 规划号比教程号多 1 |
| 教程 D08 覆盖规划 D8+D9（ReAct 工具链 + 记忆滑窗合并） | 规划号比教程号多 2 |
| 规划 D10「摘要记忆 + sessions API」被跳过、未做 | 两套号背后**内容**也差了一天 |
| 教程 D14/D15 用两天补上规划 D10 这一笔欠账 | 差额被吃掉，两套号重新并轨 |

换算关系**分三段，不要记单一公式**：

```
教程 D09 ~ D13 ：规划号 = 教程号 + 2
教程 D14 / D15 ：例外 —— 规划号 = D10（比教程号小，是补账日）
教程 D16 及以后：规划号 = 教程号（两套号数值重合）
```

⚠ **2026-09-29 修正**：本节原写「所以自教程 D09 起，换算关系固定为：规划号 = 教程号 + 2」。
但对照表里 **D16–D22 每行两套号数值相等**（D16=D16 … D22=D22，主题逐行与 PRD §13.2 对得上），
所以那句话**只对教程 D09~D13 成立**，已按上表拆分。
（`D16` / `D19` / `D20` / `D21` 几篇教程正文各自手写的编号说明内容是对的，
但说法不统一 —— **对不上号时一律以本表为准**。）

⚠ **2026-09-30 补充：出现第三种情况 —— 同一天里「主任务」与「自选加练」并存。**
D24 的主任务是 **报告生成**（规划号 = 教程号 = D24）；此外还有一份**自选加练**
「把任务变难」（甲案改问法 / 乙案加干扰文档），**PRD §13.2 里没有这一项，所以它不占号**。
命名规则随之确定：**加练文件名一律带「加练」二字**（`D24-加练-*.md`），
对照表的「规划号」列写 `—`。判据：**凡 PRD §13.2 里查不到的，都写 `—`**，
不要为了表格好看给它编一个号 —— 那正是 2026-09-29 修掉的「编号漂移」。

#### ★ ⑤ 追加修正（2026-10-02 D26，抓包实测）：「默认走哪一代」这句话，**必须带主语**

**现象**：上面那张表里原写「这句**对默认路径仍然成立**」，而 D26 写正式验证脚本时发现谈定的是 `2026-07-28`。

**对照实验**（`scripts/d26_verify.py` **F 段**，可复现；同一个 server、同一个 Client，**只改 `mode`**）：

| mode | 谈定版本 | Client → Server 的 method 序列 | 报文条数 |
|---|---|---|---|
| `auto`（**高层 `Client` 的默认值**） | **`2026-07-28`** | `server/discover` → `tools/list` | 4 |
| `legacy` | `2025-11-25` | `initialize` → `notifications/initialized` → `tools/list` | 5 |

→ **两代不是"新老替换"关系，而是"看客户端怎么连"的关系**：业务报文（`tools/list`）**一模一样**，
差的只有开场那两封（`server/discover` vs `initialize` + `notifications/initialized`）。

**机理（源码 `mcp/client/_probe.py:negotiate_auto`）**：
`mode="auto"` 先 `send_discover(LATEST_MODERN_VERSION)`，**成功就 `adopt()`（走 Modern）**，
抛错才 `session.initialize()`（回退 Legacy）。`mode="legacy"` 则直接 `initialize()`。

1. **「默认」必须带主语**：这次的错是**把一个在特定路径上成立的观测写成了通例** ——

**G 段怎么拿到"不归我管"的 pid** —— 两个可直接复用的手法：

1. **让 shell 先写 `$$` 再 `exec` 顶替**：`/bin/sh -c 'echo $$ > pidfile; exec python server.py'`
   → `exec` 之后 shell 的进程号就是 server 的进程号。**这个 pid 来自内核，不是 server 自报**。
   （`Client` 起子进程时把 pid 封在内部，正常路径拿不到。）
2. **`os.kill(pid, 0)` + `os.getpgid(pid)`** —— 不发信号，只问内核"它在不在 / 归哪个进程组"。
   实测 `getpgid(pid) == pid` → 它是**新会话的首领进程**（`stdio_client` 用 `start_new_session=True` 起的）。
   ⚠ 沙箱里 **`ps` 被拦**（`Operation not permitted`），但这两个 `os` 调用可用 —— 被拦就降级，别假设。
