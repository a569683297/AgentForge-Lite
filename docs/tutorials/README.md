## 为什么会有两套号

历史上发生过两次「一天做两天的事」+ 一次跳号：

| 事件 | 影响 |
|---|---|
| 教程 D01 覆盖规划 D1+D2（脚手架 + 分层目录合并） | 规划号比教程号多 1 |
| 教程 D08 覆盖规划 D8+D9（ReAct 工具链 + 记忆滑窗合并） | 规划号比教程号多 2 |
| 规划 D10「摘要记忆 + sessions API」被跳过、未做 | 两套号背后**内容**也差了一天 |

所以自教程 D09 起，换算关系固定为：

```
规划号 = 教程号 + 2
```

## 历史教程的过时点（复习前先看这张表）

**历史教程的正文一律不改** —— 它们是当天学习现场的记录，事后重写会让"当时怎么想的"
这件事失真。但其中有些具体结论后来被改动覆盖了，复习时**以最新实现为准**：

| 教程 | 已被覆盖的说法 | 现在是什么样 | 变更来源 |
|---|---|---|---|
| D02 | `tool_calls` 建成 `JSON` 列 | 改为 `JSONB(none_as_null=True)`：类型对齐 PRD §10，且 `None` 才真正写成 SQL NULL | 2026-09-23 D14 补丁 |
| D06 §3.4 | `should_continue` 返回 `"answer"`、图里有 `answer` 节点 | 返回 `"end"` 直接 END；`answer` 节点已**合并进 `plan`** | 同上 |
| D06（第 75 行） | `recursion_limit=10` | 显式设为 **12**。⚠ 原注释写"10"但代码**从未传给 LangGraph**，实际生效的是库默认值 25 | 同上 |
| D10（348–352 行） | 流程图含 `answer → END`；`recursion_limit=10` | 无 `answer` 节点；limit 12 | 同上 |
| D10（第 370 行） | 提出猜想"能否合并 plan #2 与 answer，省一次 LLM 调用" | **已实施** —— 就是本次改动 | 同上 |
| D11 §2.2 / 第 306 行 | D11 的引用规范写在 `answer_node` 的 system 里 | 规范整体搬进 `plan` 的 `PLAN_SYSTEM_PROMPT`，**内容一字未删**（否则引用标注会退化） | 同上 |
| 周复习 D1–D7 | `execute → plan → answer` 的连线 | 现在只有 `plan` 与 `execute` 两个节点 | 同上 |

- D08「记忆只存 user + 最终回答，不存 tool_calls/tool 消息」—— 这是 **Redis 滑窗**的规则，没变
