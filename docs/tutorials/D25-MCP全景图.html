1三角色：谁连着谁

┌──────────────────────────────────────────────────────────────┐ │ Host（宿主应用）—— 一个进程，负责“跟用户打交道 + 决定放哪些工具给模型” │ │ 例：Claude Desktop · Cursor · 本项目的 Agent 后端 │ │ │ │ ┌───────────────┐ ┌───────────────┐ │ │ │ Client A │ │ Client B │ │ │ │ （连接器，1:1） │ │ （连接器，1:1） │ │ │ └───────┬───────┘ └───────┬───────┘ │ └─────────────┼──────────────────────────────┼─────────────────┘ │ JSON-RPC 2.0 │ JSON-RPC 2.0 │ │ ┌───────▼────────┐ ┌────────▼─────────┐ │ Server 1 │ │ Server 2 │ │ 自研库存服务 │ │ Harness 官方 │ │ （D26 写） │ │ （D27 接） │ │ MCPServer │ │ harness-mcp-v2 │ └────────────────┘ └──────────────────┘
1 个 Client 只连 1 个 Server Host 可以同时开多个 Client Server 不知道彼此存在

为什么这样分层：一个 Server 一次只服务一个 Client， 于是「权限、会话、连接」都是简单的一对一；跨 Server 的编排责任被推给 Host —— 也就是我们自己的 Agent。这正是 Tool Registry 存在的位置。

2两边各能提供什么

Server 提供（三样）

  • Tools — 函数，由模型决定调用。本项目要用的就是它
  • Resources — 数据/上下文，由应用决定何时塞给模型（像只读文件）
  • Prompts — 模板化消息/工作流，通常由用户主动触发

Client 提供（当前规范只剩一样）

  • Elicitation — 服务端反过来向用户要补充信息

历史版本还有 sampling（服务端借宿主的模型能力）与 roots（告知工作目录边界）， 在新规范里已不在核心清单。协议本身在演进，讲之前先查当日口径。

3★ 两代协议：这是本次核对最大的发现

MCP 规范已经换代，但生态里两种实现同时存在，所以必须分清：

代际版本怎么确认“我们说的是同一种话”
Legacy 握手式 2025-11-25 及以前 先发一次 initialize 握手（协商协议版本 + 能力），之后整个会话沿用
Modern 逐请求式 2026-07-28 及以后 没有握手。每个请求自己在 _meta 字段里声明协议版本；HTTP 上另带 MCP-Protocol-Version 头。服务器逐请求接受或拒绝
Dual-era 双代 两者都实现 看客户端怎么开场：带 _meta 就按 Modern 走，发 initialize 就按 Legacy 走
版本对不上会发生什么：服务器返回 UnsupportedProtocolVersionError（JSON-RPC 错误码 -32022）， data 里列出它支持的版本；客户端从里面挑一个重试。 现代服务器必须实现 server/discover，让客户端能提前问清“你支持哪些版本”。
我们的位置（2026-10-01 晚实测修正）： SDK 2.2.0 同时实现两代，走哪一代看客户端怎么开场。 但实测发现：走 stdio 时它默认用「握手式」 —— 客户端发 initialize，谈定的版本是 2025-11-25 （= LATEST_HANDSHAKE_VERSION）， 不是 mcp.types.LATEST_PROTOCOL_VERSION 那个 2026-07-28。
⚠ 修正一处过度外推：本图 10-01 初版写着「LATEST_PROTOCOL_VERSION 就是 2026-07-28，Harness 仍在讲 initialize → 它处于 Legacy」，读起来像 「我们这边已经是 Modern 了、只有 Harness 落后」。 实测不是这样：2026-07-28 是规范里最新的一代， 而实现（本机 SDK + stdio 默认路径）走的是握手那一代。 把「规范新增了一代」读成「实现已经切过去了」，就是这个错的成因。
→ 连带结论：PRD §9.6.2 那句「stdio 发 initialize 握手（协议版本协商）」 对默认路径仍然成立。
SDK 常量实测：HANDSHAKE_PROTOCOL_VERSIONS = (2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25) · MODERN_PROTOCOL_VERSIONS = (2026-07-28,) · MCP_PROTOCOL_VERSION_HEADER = mcp-protocol-version（HTTP 侧用，stdio 没有头）
SDK 的 Client(mode="auto") 自带代际探测与结果缓存， 这件事不需要我们手写。但要知道它在替我们做决定 —— 以及它默认选的是哪一代（上面这条就是答案）。

4两条传输：stdio 与 Streamable HTTP

stdioStreamable HTTP
形态宿主拉起一个子进程，通过它的标准输入/输出收发 JSON-RPC连一个 HTTP 端点（POST /mcp）
部署本机、单用户远程 / 多人共享
额外成本要管子进程生命周期：启动、健康检查、崩溃重启（退避）、退出清理，防泄漏要管会话与鉴权（mcp-session-id 头、Bearer Token）
本项目用这条（Harness 默认 stdio）不用（Harness 的托管模式要走 OAuth，且需官方 Support 开账号）
为什么 stdio 反而更麻烦：子进程是别人家的程序（这里是 Node）。 它崩了、卡了、或者你没关干净，都不会让你的 Python 进程报错 —— 只会表现为“工具时好时坏”。 PRD 把「生命周期管理」和「Node 运行时依赖」列为两个独立风险，原因就在这里。
