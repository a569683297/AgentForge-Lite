## §4 核心发现：13/15 条失败是评测集自身的缺陷

### 4.1 现象

`tool_call` 类题（C 类，考"该不该调工具"）的失败率高得不正常：**30 条明细里 13 条失败**，
而 `doc_qa` 类 **90 条明细全部通过**。

### 4.2 根因

翻出 C 类题的 `reference`（**参考答案**——judge 打分时拿它当"标准答案"逐点比对）：

```
C01~C04 :  应当调用 search_documents 工具完成该请求。理由：答案在知识库制度文档里，必须先检索
C05~C07 :  应当调用 current_time 工具完成该请求。理由：问的是当前时刻，属于实时信息，知识库里没有
C08~C10 :  不应当调用任何工具，直接回答即可。理由：闲聊兼能力询问，没有需要外部信息的成分，调工具反而多余
```

**这 10 条题的 `reference` 全部是"给评测者看的元说明"**（说明"这题考什么"），
**没有一条写了答案内容**。

而 `judge_service.build_prompt` 把这句说明**原样贴进了 `【参考答案】` 那一格** ——
judge 的 system prompt 里写着"你会收到：题目、**参考答案**、检索到的片段、待评答案"，
于是它**只能按"这就是标准答案"来处理**。
→ 它会要求候选答案本身去声明/执行工具调用。
→ 但候选答案是一段**回答内容**（"现在是 2026 年 9 月 29 日 09:33:27。"），不含"我调用了工具"这句话。
→ **judge 判定"未按要求执行" → 正确性 0 分、完整性 0 分。**
（还有第三维：见 §4.4 的 faithfulness —— 那一维对 C05~C07 **结构性必 0**。）

### 4.3 证据链（C05 完整对照）

| 项 | 内容 |
|---|---|
| 题面 | 「现在几点了？」 |
| `expected_tool` | `current_time` ← **"要不要调工具"这个约束本来就在这里**（结构化字段） |
| `reference` | "应当调用 current_time 工具完成该请求。理由：…" |
| **系统实际行为** | 调用了 `current_time` 工具 ✅，回答"现在是 2026 年 9 月 29 日 09:33:27。" ✅ |
| **judge 判定** | **correctness = 0，3 次投票全部 0**，`failure_reason = hallucination` |

judge 三次投票的理由原文（`eval_case_results.judge_raw` **逐字取出**）：

```
vote0: 参考答案要求调用工具获取实时时间，答案直接编造具体时间，既未调用工具也无片段依据，完全未按要求回答。
vote1: 参考答案要求调用工具获取实时时间，答案直接编造了一个具体时间，既未调用工具也无任何片段依据。
vote2: 参考答案要求调用 current_time 工具，答案却直接编造了一个具体时间，既未调用工具也无任何片段依据。
```

> ⚠️ **勘误（2026-09-30 回查数据库后修正）**：本节初版引的理由原文是
> *"参考答案要求调用检索工具，待评答案直接给出了…，未按要求执行"* —— **那其实属于 C02**
> （题面「出差住宿费的报销标准是多少？」，`run_id=4` 的 vote0/vote1）。
> 全库 `judge_raw` 里含"住宿费"共 17 行，全部落在 C02 / A05 / B02，**没有一条属于 C05**。
> 铁证结论（系统做对、judge 给 0）成立，但**引错了原话**，已替换为逐字原文。
> 详见 [`D23-工具类题判定路径修复.md`](D23-工具类题判定路径修复.md) §1.2。

**系统完全做对了，却被判失败。**

### 4.4 关键细节：为什么 C01~C04 反而过了？

C01~C04 在三配置下基本都得 5 分（12 行里 11 行 5.0，唯一例外是 run 4 的 C02），C05~C07 则 9 行全 0。

**真正的分水岭不是"有没有调工具"——judge 对四类题都看不到工具调用**
（`build_prompt` 只发【题目】/【参考答案】/【检索到的片段】/【待评答案】四样）。
分水岭是：**答案背后有没有 judge 认得的那种依据（检索片段）。**

| case | `expected_tool` | 检索片段数 | faithfulness 维度 |
|---|---|---|---|
| C01~C04 | `search_documents` | 5~10 条 | 有据可比 → 能给高分 |
| C05~C07 | `current_time` | **0 条** | `JUDGE_SYSTEM` 的 0 档就是"**整段答案找不到任何片段依据**" → **结构性必 0** |

C02 更极端：**A 配置下 0 分、B/C 配置下 5 分，而三份答案的内容几乎相同**（run 4 内部三次投票就是 0/0/5）。
把三条理由摊开看，分歧在**读法**，不在分数档位：

```
vote0 c=0 | 参考答案要求调用检索工具，待评答案直接给出了住宿费标准，未按参考答案要求执行…
vote1 c=0 | 参考答案要求调用检索工具，待评答案直接给出了住宿费标准，未按要求执行…
vote2 c=5 | 答案准确提取了住宿费限额标准及补充规定，与参考答案要求检索制度文档的**意图一致**，
             且所有事实均可在片段中找到依据。
```

→ vote2 把"应当调用 search_documents 工具"读成**意图**（"这题想考检索"），于是去看行为与依据 → 5 分；
→ vote0/vote1 把它读成**字面要求**（"答案得说自己调了工具"）→ 0 分。

**同一句 `reference`，judge 在两处读法不同，这就是它随机性的来源。**
**C02 那条"配置差异"的真相是抽签，不是配置的效果。**

而 judge **不是瞎抽** —— 它抽到"意图"那一支时判得完全正确。
问题在于**输入太少，不足以让它稳定地抽到正确那一支**：
既没有工具调用记录（看不到行为），`reference` 又不承载答案（比文本必然冲突）。

## §6 这个 bug 为什么一直没被发现

这是本文档最该记住的部分 —— **它不是运气问题，是三个结构性原因**：

| # | 原因 | 说明 |
|---|---|---|
| ① | **"稳定的假失败"比随机噪声更难发现** | C05~C08 在**三个配置下一致失败**，看起来像一个可靠的信号（"系统在这 4 类问题上确实不行"）。**随机噪声至少会自己抖出来**，而稳定的假信号会被当成结论收下 |
| ② | **D22 的小规模实跑恰好避开了它** | 那次只跑 4 题，其中 C 类题是 C01/C02 —— 而那一次 judge **全部给了 5 分**。**样本小 → 恰好全好 → bug 隐藏**（同 D20「第 1 轮 100% 是幸存者偏差」） |
| ③ | **从数据形状上看不出异常** | C 类题 `reference` 平均 48 字，`doc_qa` 36 字、`cross_doc` 72 字 —— **长度完全正常**。这个 bug 只能靠**读 reference 的内容**发现，任何统计检查都抓不到 |

> **一句话教训**：**`reference` 不是给人看的文档，是给 judge 吃的标准答案。**
> 写它的时候必须站在 judge 的视角：*"这段文字会被当成正确答案，我的答案跟它比对会得到什么判定？"*

## §7 结论与下一步

### 7.1 诊断本身的三条结论（对 D23 的意义）

1. **答案级评分测不出三配置差异**（96% 题目完全一致，唯一差异题还是已知抖动题）→
   **不能**用这 50 条题下"重排有没有用"的结论
2. **评测集有必须先修的缺陷**（C 类题 `reference`）→ 带着这个缺陷跑消融，
   C 类题会**恒定地**贡献 4~5 条假失败，把三个配置一起压低
3. **题目整体偏简单**（剔除后 98/100/98）→ 即使修好缺陷，天花板效应依然存在

## §8 方法论收获（面试可讲）

1. **"测不出差异"要先怀疑尺子，而不是急着下"没有差异"的结论。**
   本轮如果只看表面数字（88/92/90），很容易写成"重排对答案准确率无明显提升" ——
   而真实原因有两个，且**都不是重排本身**。
2. **稳定的假失败是评测系统里最危险的一类错误。** 它有三个特征：跨配置一致、理由听起来很合理、数据形状正常。
   唯一的防线是**读原始判定理由**（judge 的 `reason` 字段），而不是只读汇总分数。
3. **给 judge 的标准答案，是"接口"不是"文档"。** 约束类信息（要不要调工具）必须走**结构化字段**
   （`expected_tool`），**不能写进自然语言的参考答案** —— 后者会被 judge 当成内容要求。
   > 这与本项目反复踩的那条同族：**同一件事写两处，两处会各自演化**。
4. **小样本通过 ≠ 没问题**。D22 那次 4 题实跑全绿，恰恰因为抽到的题"运气好"。
   样本小的时候，"全绿"的信息量远低于直觉。
