# 部署上线手册（IP 直连版）

> **目标形态**：腾讯云轻量应用服务器（国内，4核4G3M）→ `http://<公网IP>:8080` 直接访问
> **日期**：2026-10-15 ｜ **选型依据**：本机容器实测（见 §0.2）
> **后续可升级**：域名 + HTTPS + 备案（见 §10，升级时另出操作清单）

## 0. 全景

### 0.1 部署拓扑（单机四容器）

```
你的 Mac                              腾讯云轻量（Ubuntu 22.04）
┌─────────────────────┐              ┌────────────────────────────────┐
│ 项目源码 + models/   │   rsync      │  /home/ubuntu/AgentForge-Lite/ │
│ （.env 一并上传）     │ ──────────▶  │   ├─ docker-compose.yml        │
└─────────────────────┘              │   ├─ .env         （密钥）      │
                                     │   ├─ models/      （1.1 GB）   │
                                     │   └─ data/        （示例素材）  │
      浏览器访问                      │                                │
 ┌─────────────────────┐             │  docker compose 起的 4 个容器： │
 │ http://<IP>:8080    │ ◀────────── │  ┌────────┐  ┌──────────────┐  │
 │ （web 容器 nginx）   │             │  │  web   │◀─│    api       │  │
 └─────────────────────┘             │  │ :80→8080│  │(FastAPI:8000)│  │
                                     │  └────────┘  └──────┬───────┘  │
                                     │              ┌──────┴──────┐   │
                                     │              │db(pg16+向量) │   │
                                     │              │redis(缓存)   │   │
                                     │              └─────────────┘   │
                                     └────────────────────────────────┘
        api 出网调 DeepSeek API（外部付费，按 token）；可选回流 Langfuse Cloud
```

**为什么只暴露 8080**：前端 nginx 同源反代 `/api/` → api 容器（见 `frontend/nginx.conf`），
对外**只需要一个入口端口**。现有 compose 已映射 `8080:80`，IP 直连形态**服务端零改动**。

### 1.2 防火墙放行 8080（★ 最容易漏的一步）

**「控制台」是网页，不是软件** —— 和你 Mac 的本机设置无关，不用安装任何东西。
用浏览器（Safari / Chrome）打开下面这个直达链接，登录你买服务器的账号：

```
https://console.cloud.tencent.com/lighthouse/instance/index
```

> 注意别走错产品：是「**轻量应用服务器**」，不是「云服务器 CVM」（长得很像，进错找不到实例）。

操作路径：**服务器列表 → 点进你的实例（进入详情页）→ 「防火墙」页签 → 「添加规则」**，
在「创建新的规则」窗口里填：

| 字段 | 填什么 |
|---|---|
| 应用类型 | 自定义 |
| 来源 | `0.0.0.0/0`（默认值，对所有 IP 开放） |
| 协议 | TCP |
| 端口 | **8080** |
| 策略 | 允许 |
| 备注 | 选填，如 agentforge-web |

点「确定」即生效（无需重启实例）。

> 实例默认已放通 22（SSH）/ 80（HTTP）/ ICMP，**8080 必须手动加**。不加这条，
> 外网访问 8080 会一直超时，而服务器内部 `curl localhost:8080` 却是通的 —— 排查时别被这个迷惑。
> （依据官方文档《管理实例防火墙》：cloud.tencent.com/document/product/1207/44577）

## 2. 服务器初始化（SSH 登录后操作，约 10 分钟）

### 2.1 SSH 登录（在 Mac 终端执行）

```bash
ssh ubuntu@<SERVER_IP>
# ★ 实测踩坑：Ubuntu 镜像的默认登录用户是 ubuntu，不是 root！
#   （root 密码登录被腾讯云默认禁用；需要 root 权限就加 sudo——ubuntu 用户免密 sudo。）
#   首次连接输入 yes，再输密码。
```

### 2.2 安装 Docker（若用过 Docker 应用镜像则可跳过）

> ★ 本节为 **2026-10-16 实测通过**方案。不走 get.docker.com 官方脚本（国内拉取不稳），
> 改用**腾讯云 docker-ce 镜像源 + apt**。
> 注意域名：`mirrors.cloud.tencent.com` 可用；`mirrors.cloud.tencentyun.com` 这个子域实测**不可达**，别用。

```bash
# 1) 基础工具
sudo apt-get update -qq
sudo apt-get install -y ca-certificates curl gnupg

# 2) 添加 docker-ce 镜像源
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg | \
  sudo gpg --dearmor --yes -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu jammy stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list

# 3) 安装 + 开机自启 + 免 sudo 使用
sudo apt-get update -qq
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu     # 重新登录后生效

# 4) 验证（两条都要有输出；实测版本：Docker 29.9.1 / Compose v5.6.0）
docker --version
docker compose version     # 需要 v2（命令形如 docker compose，不是 docker-compose）
```

### 2.3 配置 Docker 镜像加速器（★ 不配会拉不动镜像）

国内直连 Docker Hub 拉取 `pgvector/pgvector` 等基础镜像会超时，改用腾讯云内网加速：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
systemctl daemon-reload && systemctl restart docker

# 验证：能拉下一个小镜像即成功
docker run --rm hello-world
```

> `mirror.ccs.tencentyun.com` 是腾讯云**内网**地址（仅腾讯云服务器可用），这也是选腾讯云的原因之一。
> 附带配了日志轮转（单文件 10MB×3），防止容器日志把磁盘撑爆。

### 2.4 加 2 GB Swap（4G 内存的保险，强烈建议）

构建阶段（tsc 类型检查 + 打包）会出现内存峰值；有 swap 兜底可避免被 OOM 杀掉：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

free -h    # 验证：Swap 一行显示 2.0Gi
```

## 3. 上传代码与模型（在 Mac 上执行，10-30 分钟）

### 3.1 传代码 + .env + 示例素材（约 1 分钟）

```bash
# 在 Mac 终端，进入项目根目录
cd /Users/779369901qq.com/workspace/bs/AgentForge-Lite

rsync -avzP \
  --exclude '/.git' --exclude '/.venv' --exclude 'node_modules' \
  --exclude '/models' --exclude '/logs' --exclude '.pytest_cache' \
  --exclude '__pycache__' --exclude '*.pyc' --exclude '.DS_Store' \
  --exclude '.coverage' \
  ./ ubuntu@<SERVER_IP>:/home/ubuntu/AgentForge-Lite/
```

> ⚠️ **锚定陷阱（2026-10-16 实测踩坑）**：`--exclude 'models'` 这种**不带 `/` 的模式会在任意层级匹配**——
> 它会把顶层的模型缓存目录排掉，**顺带把 `app/models/`（ORM 代码包）也排掉**，
> 后果是容器启动直接崩：`ModuleNotFoundError: No module named 'app.models'`。
> 所以 `models` 和 `logs` 这两条必须写成 `'/models'`、`'/logs'`（加了 `/` 才只匹配根目录）。

说明：
- `.env`（含真实密钥）**会一并上传** —— 走 SSH 加密通道，且免去在服务器上重填；
- `models/` 被排除，下一步单独传（大文件单独走，失败可单独重试）；
- 排除 `node_modules`/`.venv` 是因为容器里会重新装（本地版本与服务器架构不同，传了也没用）；
- 本次部署已在本机配好专用密钥：命令里加 `-e "ssh -i ~/.ssh/agentforge_deploy"` 可免密执行
  （不加则回车输密码；密钥文件在本机 `~/.ssh/agentforge_deploy`）。

传完顺手收紧权限（在服务器上执行）：

```bash
chmod 600 /home/ubuntu/AgentForge-Lite/.env
```

### 3.2 传模型（1.1 GB，约 5-20 分钟，取决于家宽上行）

## 8. 服务器形态的已知边界（如实登记，别当故障）

| 现象 | 原因 | 影响 |
|---|---|---|
| `/api/tools` 只有 3 个工具（无 `harness`） | api 镜像**不含 Node**，compose 强制 `MCP_HARNESS_ENABLED=false`（README §4.3） | 演示「外部系统互操作」段**跳过**，其余不受影响 |
| 不需要跑 `make warmup` | 同上，宿主机无 Node 且外部工具已关 | 无影响；跑了也会明确报"前置不满足" |
| 浏览器提示"不安全" | 无 HTTPS（IP 直连形态无证书；Let's Encrypt 不给 IP 签证书） | 功能正常；升级域名后解决（§10） |
| Langfuse 追踪可能超时 | Langfuse Cloud 在海外，国内服务器访问不稳 | 可选功能，缺了只少追踪数据；失败不影响问答主链路 |
| 首次提问慢数秒 | 本地模型懒加载（设计如此） | 一次性 |
| **服务器重启后站点打不开** | `docker-compose.yml` 里 db/redis **刻意没配** restart 策略（避免每次 `up` 误判重建容器）；api/web 有 `restart: unless-stopped`，起来了但连不上 db | 手动恢复：`cd /home/ubuntu/AgentForge-Lite && docker compose up -d`。要一劳永逸 → 给 db/redis 加 restart 策略（单独一次提交，会各重建一次容器，数据在 pgdata 卷里不丢） |

## 9. 故障排查

| 症状 | 排查顺序 |
|---|---|
| 外网 8080 打不开，但服务器内 `curl localhost:8080` 通 | ★ 十有八九是**腾讯云防火墙没放行 8080**（§1.2） |
| 外网、内网都打不开 | `docker compose ps` 看 web 容器是否 Up；`docker compose logs web` |
| api 容器一直 unhealthy | `docker compose logs api`；常见是 .env 缺失/不对（数据库密码） |
| api 容器反复重启，日志 `ModuleNotFoundError: No module named 'app.models'` | ★ rsync 排除模式**没锚定**：`--exclude 'models'` 会匹配任意层级、误排顶层 `app/models/`（ORM 包）。必须写 `--exclude '/models'`（只排顶层模型目录）。修复后补传文件并重建 api 镜像 |
| 构建卡在 `uv sync`（每秒几十 KB） | 检查 Dockerfile 是否用了旧版（无 uv.lock 替换那行）——见 §0.4 |
| 构建日志出现 `only one connection allowed` / `context canceled` 且彻底卡死 | BuildKit 会话卡死（偶发）。`sudo systemctl restart docker` 后重新构建即可，镜像层缓存不丢 |
| 构建中进程被杀（OOM） | 确认 swap 已开（§2.4）；`docker compose down` 后再构建 |
| 页面能开、提问报错 | `.env` 的 `DEEPSEEK_API_KEY` 无效/欠费；`docker compose restart api` |
| 页面能开、上传文档报 500 | 十有八九是**没跑 §5.1 建表**；重跑该节 7 个脚本（幂等） |
| 拉镜像超时 | 复查 §2.3 加速器配置（`docker info` 里能看到 Registry Mirrors） |
| 批量跑远程命令时，只有第一条执行、后面"静默消失" | SSH heredoc 的 stdin 被第一条 `docker exec` 吃掉（不影响部署结果）。给每条 `docker exec` 显式加 `< /dev/null` 即可 |
