## 三、问题一：BM25 检索实现（项目 D14 / PRD D16）衔接判定

**结论：衔接正确，未越级。但它前面隔着一整天的欠账。**

### 3.1 序列检查

PRD.md 的 M3 段落是连续的：

```
D15 学 BM25 + tsvector 原理   →   D16 BM25 检索实现   →   D17 RRF 混合检索
   ↑ 项目 D13 已完成                  ↑ 项目 D14 待做            ↑ 未到
```

- D16 的**直接前置是 D15**（学原理），而 D15 **已完成**（项目 D13，教程 `D13-BM25与tsvector原理.md` + 探针 `scripts/d13_probe_retrieval.py`）
- D16 不依赖任何其他未完成项 → **衔接正确** ✅

### 3.2 但欠账在更早的地方

```
PRD:  D8+D9 ──────→ D10 ─────────────────→ D11+D12 ──→ D13 ─→ D14 ─→ D15 ─→ D16
项目:  D08 完成     ❌ 整块缺失              D09 完成    D10+D11  D12    D13    待做
                    ↑
              项目在这里直接从 D08 跳到了 D11 的内容
```

**准确表述**：项目没有在 D15→D16 处跳步，但**在更早的 D09→D11 之间已经越过了 D10**。所以：

- 问"BM25 实现是否衔接正确" → **是**
- 问"整体账是否连续" → **否，中间缺一整天**

### 3.3 D14 尚未开工的说明

**「BM25 检索实现」目前还不存在任何代码或文档。** 上一轮给出的是一份**方案**（5 个文件的改造计划 + 5 个待拍板决策），因等待确认而未动工。D13 的产出是**原理教程 + 只读探针**，不是检索实现。

## 五、D03 缺号的准确成因（有依据）

**不是漏做，是编号顺延**。memory `2026-08-29.md` 原文：

> 用户发现计划偏差并核对：PRD 中 Redis 是 D4 任务，但我在 D3 讲了 Redis——因为 D2 实际合并了 D2+D3 内容（分层+ORM+建表一次完成），我未说明天序顺延。
> **用户选择选项 1**：接受「D2 已含 D3 内容」，今天实际执行**原 D4**，后续天序顺延。

即：项目第 3 天做的是 PRD D4（Redis）的任务，教程命名随之写成 `D04`。

**真正的问题是**：这个说明只存在于 memory，**教程目录里没有任何标注**。任何人翻目录看到 `D02 → D04` 都会以为漏号了。
