## 一、背景与目标

**背景**：平台所有对话目前一律走云端 API（deepseek，失败降级中转 GPT）。日常使用中，大量请求是"闲聊、常识、文本润色"这类轻任务，不需要检索也不需要工具 —— 这类请求走云端既慢（网络往返）又费 token。

**目标**：接入本机 Ollama（`qwen2.5:7b`）作为**第三个 LLM 通道**，在**前端对话台**提供模型切换（云端 / 本地），用户手动选择。功能边界明确：**本地模型只接轻任务，凡涉及知识库检索、工具编排、评测的一律走云端**（依据见第三节）。

**非目标**（本次不做）：
- ❌ 自动分流（"后端自己判断简单/复杂"）—— 不可靠，留到第二步（见 5.4）
- ❌ 评测 judge / 对话摘要切本地 —— 理由见 3.3、3.4
- ❌ 前端之外的入口（如评测脚本）走本地

## 二、实测依据（可行性事实）

以下全部为本机 2026-10-12 实测结果，非推测：

| 验证项 | 结果 |
|---|---|
| Ollama 服务 | v0.35.0 运行中，监听 `localhost:11434` |
| 可用模型 | `qwen2.5:7b`（Q4_K_M 量化，7.6B，context 32768）、`bge-m3`（embedding，本项目未用） |
| **函数调用能力** | `qwen2.5:7b` 的 capabilities 含 **`tools`**；实测发 `tools` 参数后返回标准 `tool_calls`（调用 `current_time`，`finish_reason: "tool_calls"`），**格式完全符合 OpenAI 协议** |
| OpenAI 兼容端点 | `http://localhost:11434/v1/chat/completions` 返回标准格式（`choices[].message`、`usage.prompt_tokens` 等）→ **现有 `llm_gateway._call_once` 零改动可对接** |
| **容器访问宿主机** | 容器内 `localhost:11434` → Connection refused；**`host.docker.internal:11434` → HTTP 200** ✅ |

> **名词注解**：
> - **Ollama**：本机运行大模型的工具，下载模型后在本地推理，对外提供 HTTP 接口（含 OpenAI 兼容协议），不联网、不花钱。
> - **function calling（函数调用）**：让 LLM 输出"我要调用某工具 + 参数"的结构化结果，Agent 据此执行工具。AgentForge 的 ReAct 循环（推理⇄执行工具）依赖这个能力。
> - **`host.docker.internal`**：Docker 容器内访问**宿主机**的特殊域名。容器里的 `localhost` 指容器自己，不是宿主机 —— 这是接入本地模型最容易踩的坑（已实测确认）。

**现存架构的有利条件**（为什么改动小）：
- 网关本就是多通道抽象：`LLM_CHANNELS = ("deepseek", "openai")`，每通道 = `{api_key, base_url, model}` 三件套；
- D22 已实现 `provider=` **锁定通道**能力（judge 在用）→ 本地模型可复用同一机制；
- 项目已有本地模型先例：embedding 走 fastembed 本地、rerank 走本地 ONNX —— "chat 也接本地"不破坏架构一致性。

## 三、场景边界：什么用本地、什么用云端

**判断框架**（一个功能能否用本地 7b，看三点）：
① 要不要**精确引用/忠实度**（7b 知识有限、易加戏改事实）
② 要不要**多步工具编排**（7b 稳定性弱于 deepseek）
③ 结果是不是**量具**（打分/评估类，必须锁死可比）

### 3.1 ✅ 用本地 qwen2.5:7b

| 场景 | 说明 |
|---|---|
| 纯闲聊/寒暄 | 无引用、无工具 |
| 常识问答（不涉及公司内部资料） | 通用知识 7b 本身具备 |
| 用户粘贴文本的润色/改写/翻译/总结 | 纯生成，不依赖知识库 |
| 无工具、无检索的单轮简单问答 | 同上 |

### 3.2 ❌ 必须用云端 deepseek

| 场景 | 调用点 | 理由 |
|---|---|---|
| RAG 检索问答（制度/项目/数据） | agent 主循环 | 要引用定位 + 忠实度 + 抗幻觉；评测 98% 成绩基于 deepseek |
| 多步工具编排（ReAct 下钻） | agent 主循环 | 7b 工具遵循度弱（单次调用已实测通过，**多轮编排未验证**，标注为风险） |

### 3.3 ❌ 评测 judge 绝对不切

judge 是评测的"**量具**"（衡量标准本身）。换模型 = 换了一把尺子，历史分数立刻不可比。项目 D22 已明确"judge 必须锁定通道"，本次不动。

### 3.4 ❌ 对话摘要默认不切

摘要要求"**忠实压缩、不加戏、不改事实**"，且摘要会注入后续每轮 prompt（错误会放大）。7b 的代际漂移风险高于 deepseek。本次不动。

> **边界一句话**：本地模型只接"不需要知识库、不需要工具"的轻生成任务；碰检索、碰工具、碰评测的，一律留在云端。

## 四、技术方案

### 4.1 端到端链路（入口 → 步骤 → 返回）

```
[前端] 对话台"模型"下拉框（云端/本地）
   │  用户选择 → 随请求发送 provider 字段
   ▼
[HTTP] POST /api/chat  { message, session_id, provider? }
   │  provider 缺省 = 现有行为（云端主通道+降级），零回归
   ▼
[API 层] app/api/chat.py：把 req.provider 透传给 run_agent
   ▼
[服务层] run_agent(session_id, user_input, provider=...)
   │  provider 写入 AgentState（新增 NotRequired 字段）
   ▼
[编排层] plan_node → chat_with_tools(..., provider=state.get("provider"))
   ▼
[网关] _resolve_channels 锁定通道 → _call_once 走 ollama 的 base_url
   ▼
[Ollama] http://host.docker.internal:11434/v1/chat/completions → qwen2.5:7b
   ▼
返回：ChatResult + model_used（前端显示"本轮由 XXX 回答"）
```

### 4.2 后端改动点清单

| # | 文件 | 改动 |
|---|---|---|
| B1 | `app/config.py` | ① `LLM_CHANNELS` 加 `"ollama"`；② 新增字段 `ollama_base_url`（默认 `http://host.docker.internal:11434/v1`）、`ollama_chat_model`（默认 `qwen2.5:7b`）、`ollama_api_key`（占位，Ollama 不校验）；③ `llm_channel()` 加 `ollama` 分支；④ `SENSITIVE_FIELDS` 视需要加 `ollama_api_key`（本地不需要真 key，可不加，评审时定） |
| B2 | `app/schemas/chat.py` | ① `ChatRequest` 新增 `provider: str \| None`（校验取值 ∈ `LLM_CHANNELS`，非法值 422）；② `ChatResult` 新增 `model_used: str`（本轮实际使用的通道标签，供前端归因显示） |
| B3 | `app/api/chat.py` | `run_agent(session_id, req.message, provider=req.provider)` 透传；响应带 `model_used` |
| B4 | `app/services/agent_service.py` | ① `AgentState` 加 `provider: NotRequired[str \| None]`；② `run_agent` 加 `provider` 参数（默认 None=旧行为）并写入 state；③ `plan_node` 把 provider 透传给 `chat_with_tools` |
| B5 | `.env` / `.env.example` | 新增 `OLLAMA_BASE_URL` / `OLLAMA_CHAT_MODEL`（`.env.example` 带注释说明 `host.docker.internal` 的由来） |

**网关层（`llm_gateway.py`）预计零改动** —— `_call_with_failover` 已返回实际通道标签，只需把 `result["provider"]` 往上带即可（落在 B4/B3 的透传里）。

### 4.3 前端改动点清单

| # | 文件 | 改动 |
|---|---|---|
| F1 | `frontend/src/types/api.ts` | `ChatRequest` 类型加 `provider?: string`；`ChatResponse` 加 `model_used: string` |
| F2 | `frontend/src/api/chat.ts` | `sendMessage` 加 `provider` 参数（可选，不传=旧行为） |
| F3 | `frontend/src/pages/ChatPage.tsx` | 输入区（composer）加"模型"下拉框：`云端（deepseek）` / `本地（qwen2.5:7b）`，默认云端；发送时带上；消息卡片显示"本轮由 XXX 回答" |
| F4 | `frontend/src/styles/chat.module.css` | 下拉框样式（跟随现有 composer 风格） |

**UI 位置建议**：放在输入框下方 `composerTools` 行（与"Enter 发送"提示同排）—— 它是"本次发送的参数"，和发送动作用户心智一致；不放侧边栏（避免与"会话"混淆）。

### 4.4 明确不改的部分（零回归保证）

- 评测 judge（`judge_service.py`）：继续锁定 deepseek；
- 对话摘要（`memory_service.py`）：继续走默认通道；
- 评测脚本 / 回归脚本：不传 provider → 行为与现在**完全一致**；
- Langfuse 观测：现有机制自动记录实际模型，**无需改动**（白赚的收益）。

## 五、设计决策点与推荐

### 5.1 通道命名：`ollama`（推荐）
与现有 `deepseek` / `openai` 协议名风格一致。注意：`openai` 在本项目指"OpenAI 兼容协议通道"（实际配的是中转），`ollama` 名不会与它混淆。

### 5.2 降级语义：**推荐"锁定不降级"**

本地模式失败时（Ollama 未启动/超时），**锁定报错**，不自动切云端。理由：
1. **用户选本地的核心动机就是"不烧云端 token"**（省钱/隐私/测试）。静默降级到云端 = 既违背意图、又照样花钱；
2. 失败信息透明（"本地模型不可用，请检查 Ollama 服务"），用户可自行修复或手动切回云端；
3. 与 judge 锁定通道同一哲学：**显式选择即承诺，不偷偷换**。

### 5.3 响应带 `model_used`（推荐做）
即使锁定模式，前端显示"本轮由 本地 qwen2.5:7b 回答"也有价值（归因）；且为将来可能的降级预留字段。

### 5.4 自动分流：本次不做（推荐）
自动判断"简单/复杂"本身不可靠（信号词会误判）。先手动跑顺，收集真实使用数据后再评估是否需要自动化。

## 七、验收标准

1. 前端对话台可切换「云端 / 本地」，默认云端；
2. 选本地发问 → 回答由 `qwen2.5:7b` 产出，消息卡显示实际模型；Langfuse trace 中模型名为 `qwen2.5:7b`；
3. 选云端发问 → 行为与改动前**逐字节一致**（零回归）；
4. 本地模式且 Ollama 未启动 → 返回明确错误信息（不静默降级）；
5. 现有测试（pytest + 5 脚本回归）全绿；
6. 不传 `provider` 的任何现有调用（评测脚本等）不受影响。

## 八、风险与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **7b 多轮工具编排稳定性未验证**（单次调用已通过） | 中 | 定位就是"轻任务"；实施 S1 后补一个多轮工具场景实测，不合格则收窄为"纯 chat 无工具" |
| R2 | **Ollama 默认上下文长度可能偏小**（实测无 `OLLAMA_*` 环境变量，模型自身支持 32768；服务端默认值**推测为 4096，待验证**）→ 长 prompt 可能被静默截断 | 中 | S1 阶段实测长 prompt 行为；若截断，设 `OLLAMA_CONTEXT_LENGTH=8192` 并重启 Ollama（不改本项目代码） |
| R3 | 本地推理慢（7b 在 Apple Silicon 可跑，但首 token 延迟高于 API） | 低 | 定位轻任务；前端不做超时收紧（沿用网关 60s） |
| R4 | `host.docker.internal` 仅 Docker Desktop（macOS/Windows）可用，Linux 原生 Docker 需额外配置 | 低 | 当前环境是 macOS，实测通过；在 `.env.example` 注释说明 |
| R5 | Ollama 单实例并发有限，多人同时用会排队 | 低 | 学习/演示场景单用户，可接受；写入已知限制 |
