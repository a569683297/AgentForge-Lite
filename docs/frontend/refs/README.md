# refs/ —— 界面参考图（截图存放处）

> 规则与理由见 `../DESIGN.md` §1.2。这里只写**怎么操作**。

## 一句话

**打开成熟产品，截一张图，按下面的命名丢进来。就是截图，不是设计稿。**

## 命名

```
来源-页面-日期.png
```

例：`langfuse-trace-detail-2026-10-04.png`

## 收哪几张（优先不需要注册账号的）

| # | 来源 | 截什么 | 备注 |
|---|---|---|---|
| 1 | **本机 Dify** → `http://localhost` → **`聊天机器人`** 应用的编排页 | 工作流画布：节点连线、运行状态着色 | ★ **最容易拿到的"真实产品内部界面"** |
| 2 | Langfuse 官网 / 公开 demo | trace 详情页 | **和你第一页要做的东西同类** |
| 3 | Linear 官网 | 问题列表页 | 看列表密度、近乎无色的骨架 |
| 4 | Vercel 官网 Dashboard 介绍页 | 项目概览 | 看层级怎么用描边表达 |
| 5 | Datadog APM 文档页 | trace waterfall | 看横向 span 图的比例感 |

> 第 1 张注意：`陪跑` 是**聊天助手**（只有提示词编排面板，没有画布）；
> `聊天机器人` 是 **Chatflow** 类型，**只有它有节点画布**。

## ⚠ 两条纪律

1. **只要真人产品的截图。** 不要 Dribbble / Behance 的概念稿 —— 好看，但落不成代码。
2. **不构成开工门槛。** 搭 Trace 页之前手边有 **1 张**同类截图（第 2 或第 5 张）就够，其余边做边补。
   参考图的作用是**给你自己当标尺**，不是给 AI 的投喂材料 —— 所以它不该拦住开工。
