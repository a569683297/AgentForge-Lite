## 前置确认：前端原来只有"菜单层"权限（用户要求先确认）

- 菜单层**有**：`AppShell.tsx` 的 `isAdmin = user.role === 'admin'` + `adminOnly` 过滤，
  普通用户只见 `对话台/我的画像/知识库/检索检查器`。
- 路由层**没有**：`App.tsx` 的 `/admin` 直接挂 `<AdminPage />`，无守卫；`AdminPage.tsx` 注释
  明确写"不做角色判断，由后端说了算"。普通用户手输 URL 能打开空壳页，接口全 403。
- 结论：安全由后端兜底，但用户看到的是错误提示和空表格，分不清"没权限"和"系统坏了"。

### 踩到的 / 要注意的

- 前端测试里 `ADMIN` 直接 `{...BASE, role:'admin'}` 会继承 BASE 的清单（不含 `admin.users`）→
  断言失败。这不是实现错，恰好证明"只看清单、不看 role"。测试数据必须显式写 permissions。
- `hasPermissionOf(null)` 必须返回 false，不能和"清单缺失"合并；App 未登录时虽早返回不走守卫，
  但语义上必须区分，否则这个函数被别处复用时就是越权口子。
- `docker compose exec web grep ... /assets/*.js` 的 glob 会被**宿主机 zsh** 展开而报
  "no matches found"，必须 `sh -c` 包起来在容器内展开。
